# GInsStream 项目当前状态

> 状态快照：2026-09-15。本文是 `skills/` 的现状索引，依据 `issue/` 目录记录文件和当前源码/配置扫描整理。各专题文档中的历史实验仍保留，但若与本文冲突，以本文和当前源码/配置为准。本轮新增 INS 配置三段 schema（`ins`/`ins_tc`/`ins_lc`）与机械编排发散根因修复（`acce_bias_std_si` 初值、零偏 τ 过程模型），见 [第 4.4 节](#44-配置-schema-与键归属) 与 `issue/9-14机械编排发散.md`。

## 1. 工作区与文档规则

- 当前分支为 `main`。配置集中在 `data/`（CPT 参考数据）、`data-great/`（GREAT campus01 单频 strict-float 对照：`rtktc-rate.yaml` / `rtktc-increment.yaml`）、`phone/`（手机 RTD-TC）。`data-great/config/` 旧实验配置树与 `data-great/output/` 下 27 个过时输出目录已于 2026-09-15 清理，仅保留三个正式输出目录。`data/rtk-tc-ganbi.yaml` 为 0 字节空文件，无害保留。
- `src/core/ins/` 是当前 INS/松组合实现目录，`src/core/tc/` 是紧组合实现目录，`src/core/gnss/` 保持纯 GNSS 解算与 RTKLIB 适配。
- 当前实现采用单滤波 EKF；`GInsStream.md`、`imu.md` 等文件中仍存在双滤波、旧 `core/imu`/`core/estimator` 路径等历史设计章节，只能作为演进记录。
- 所有实验必须保留配置、输入、命令、输出和 `Tdata/Texp`；候选修改必须先跑纯 GNSS，再跑组合导航，并用同一窗口、真值和评估规则对比。

## 3. GNSS 与 BDS 当前结论

### 3.1 RTK 浮点与固定

- `gnss.prnbias=0.03` 是已验证的 RTK 浮点基线；旧值 `0.5` 会令模糊度协方差托底过大，使解退化到码级。
- 门限语义必须分开：`maxinno` 是载波相位双差门限，RTK 当前建议/最终裁定为 `5.0`；`maxcode` 是伪距门限，通常为 `30.0`。把相位门限放宽到 `30` 会放过未初始化模糊度行。
- TC 模糊度管理已完成 LD 异常降级、SD→DD LAMBDA、正定保护、过程噪声和健康门控；独立 `armode=3` 分支在目标窗口约 `0.019 m` 水平 RMSE，但正式 MECH-16 基线仍需与 AR 分支分开报告。

### 3.2 BDS/Data19

- 已修复 BDS GEO 轨道旋转、BDS 独立接收机钟差、BDT 星历转 GPST 的 14 s、基站 RINEX 类型分组列映射，以及未初始化相位行进入 DD 的问题。
- Data19 HG4930 GPS+BDS RTK：gipylib FIX 率约 `99.7%`，水平 RMSE `0.0582 m`，与 RTKLIB 双 FIX 结果差异约 `2.7 cm`；GPS-only 回归不受影响。
- BDS-only RTK 仍为 `0%` FIX（与金标准现象一致），浮点精度差距仍待专项分析。
- Data19 TC 的 IMU 数据存在约 `0.75--0.85 s` 非恒定时标滞后；已增加 `ins.imu_time_offset_s`，已验证 `-0.85` 可将 TC 水平中位误差从约 `6.05 m` 降至约 `2.00 m`，但仍不等同于完全解决。

## 4. INS/TC/LC 当前基线与边界

### 4.1 过程噪声边界

- **`pos_psd` / `vel_psd` 是松组合专属参数，已从机制上禁止用于紧组合**。2026-09-15 起 INS 配置拆分为 `ins`（共用）/ `ins_tc`（仅 `tc`）/ `ins_lc`（仅 `lc`）三段，二者登记在 `config_loader.INS_LC_ONLY_KEYS`；写在共用 `ins` 段且 `ins.enabled='tc'` 时，加载器直接抛 `ValueError`。TC 的历史 `pos_psd=1e-8` / `vel_psd` 注入量（远低于速度积分传播，逐位无影响）已移入休眠的 `ins_lc` 段。
- TC 运行点：RTK TC MECH-16 使用 `vel_psd=0`（在 `ins_lc` 段休眠）和 `vel_var_floor=3e-4`，以维持稳定运行点而不注入位置随机游走。
- LC：不能照搬 TC 的 `pos_psd=0`。实测会造成位置协方差坍缩、滤波锁死和速度尖峰；`config.yaml`/`spp-ins-lc.yaml` 的 `pos_psd` 写在 `ins_lc` 段生效。
- 该边界是由量测可观测性决定的，不能把某个数据集的 `vel_psd`、`vel_var_floor` 或加计零偏初值当作全局默认值。

### 4.2 RTK-INS TC

- 正式 MECH-16/FINAL4 证据：目标窗口 SOW `359000--359100` 水平 RMSE `0.0394 m`，全段 `0.2595 m`，传播速度 RMSE 约 `0.099 m/s`，量测间速度增长约 `8.0 cm/s`。
- `pos_psd=5` 引起的约 `1 m/s` 速度常偏已定位并通过 TC 的 `pos_psd=0` 消除；当前剩余差距主要涉及姿态游走和 GNSS 浮点残差闭环。
- ignav `.stat` 只有 1 Hz 更新状态，不能作为 gipylib 100 Hz 量测间漂移的严格金标准；不得声称逐历元完全一致。

### 4.3 RTK-INS LC 与 SPP-INS

- RTK-LC 曾在 `armode=3 + combined + NHC` 实验配置下达到 `0.2455 m` 3D RMSE；NHC 只适合车辆运动假设，不能默认用于可侧向飞行数据。
- SPP-LC 约 `3.43 m` 3D RMSE，平面约 `0.77 m`，主要受 SPP 高程系统误差约 `3.29 m` 限制，未达到 `<2 m` 三维目标。
- SPP-TC 约 `4.13 m` 3D RMSE，偏航初始化收敛慢；后续候选应优先考虑 Doppler 速度量测或可验证的航向可观性改进。

### 4.4 配置 schema 与键归属（2026-09-15）

INS 参数按是否需要区分松紧组合拆成三段，加载器（`config_loader._merge_mode_specific_ins`）按 `ins.enabled` 合并对应段，业务代码只看到合并后的 `ins`：

| 段 | 含义 | 生效 |
|---|---|---|
| `ins` | 松紧组合共用 | 始终 |
| `ins_tc` | 紧组合专属（或覆盖值） | `ins.enabled='tc'` |
| `ins_lc` | 松组合专属（或覆盖值） | `ins.enabled='lc'` |

- `ins.enabled='off'` 时两段都不合并；未激活的段允许保留作对照。
- **LC-only 专属键**（写在 `ins`/`ins_tc` 且 `tc` 模式直接报错）：`pos_psd`、`vel_psd`、`gnss_vel_std`、`gnss_sd_scale`、`gnss_sd_axis_scale`、`gnss_time_sync_noise_s`、`use_reported_gnss_sd`、`vertical_sigma_factor`、`pos_diff_vel_std`、`position_diff_velocity_update`、`innov_reject_threshold`、`innov_reject_warmup`。
- **TC-only 专属键**：`tc_use_doppler`。
- **共用参数（两种模式都用）**：`nhc_warmup`（`lc_integration.py:108` 与 `tc_integration.py:143` 都消费；曾因写在 `ins_lc` 段导致 `spp-ins-tc.yaml` 的 `nhc_warmup=10` 在 TC 下静默退回默认 30，已修正到共用 `ins` 段）。
- **废弃死键**（任何 ins 段出现即报错，无消费点）：`rtk_float_pos_std`、`pos_diff_vel_max_std`。

键归属以源码消费点为准，新增 INS 键若只在 LC 或 TC 消费方出现，须同步登记到 `INS_LC_ONLY_KEYS` / `INS_TC_ONLY_KEYS` / `DEPRECATED_INS_KEYS`，否则跨模式校验会漏报。

## 5. 手机 RTD-TC 当前结论

- 手机 RTD-TC 已将问题从“数百米发散”校正为 TC 更新点相对纯 RTD 明显变差：正式结果水平 RMSE 约 `7.72 m`，改前约 `14.45 m`，纯 RTD 约 `3.58 m`。
- 当前已采纳 `gnss_t=[GPS,GAL]`，暂停 BDS；`maxcode=60` 是数据集专用的已验证候选，不能推广为通用伪距门限。BDS 恢复前必须完成逐卫星残差、频率映射和 RTKLIB C 对照。
- 手机 TC 的主要剩余风险是姿态/重力泄漏、零杆臂与安装角、GNSS 观测筛选、时间覆盖和更新反馈；必须按“纯 RTD → RTD-TC”顺序逐变量验证。

## 6. 约束、抗差和输出

- NHC/ZUPT/ZARU 已拆为 `src/core/motion/` 设计；默认均关闭。NHC 的 `max_vel=0.5`、`std=0.05` 是对齐 ignav 的车辆约束实验值，不能用于未知安装方向或明显侧向/坡度运动而不验证。
- `src/core/robust/` 仍是抗差估计接口预留，主滤波当前不调用。
- stat/trace 已支持开关、基础状态、TC 更新点协方差/创新/增益摘要、RUN_START/RUN_END 和有限值诊断；S4 逐卫星、逐模糊度和矩阵明细需与浮点协方差专项合并后再实现。

## 7. 未完成事项与停止点

1. 浮点协方差与 ignav 的差距尚未通过单一通用 R 语义解决；直接对齐 `eratio` 或相位误差会恶化关键窗口，联合调优已按底线关闭。
2. 手机 BDS 恢复、逐卫星残差 dump、RTKLIB 观测码/频点选择逐观测对齐仍是独立专项。
3. Data19 IMU 非恒定时标、自适应时间同步和 TC 更新反馈增益仍有剩余差距。
4. 任何参考 ignav 的状态、Q/R、观测选择或评估语义若导致关键指标恶化，必须保留证据、回退到最近通过基线并记录 `ASK-xx[Texp]`，未获新指示前只做只读分析。
