## 1. 概述

### 1.1 设计目标

INS 初始化是组合导航的入口阶段，目标是在系统启动后，**当首次匹配到 GNSS 数据时**，利用 GNSS 解算结果（位置/速度）和 IMU 观测数据，确定 INS 的初始位置、初始速度、初始姿态以及 IMU 误差参数，并装配初始协方差矩阵，为后续 EKF 机械编排与组合导航提供可信的初始状态。

**核心要求**（用户原话）：
1. 当匹配到了 GNSS 数据，需要将 IMU 数据对齐到 GNSS 观测数据的时间戳
2. 时间对齐策略：本项目对速率式 IMU（gyro/accel）使用前后历元间的时间比例线性插值，在 GNSS 时刻生成测量值（详见第 4 节）。
3. **时间对齐时 GNSS 时间戳之前要有 IMU 数据，后面也要有一个 IMU 数据**（包夹条件，详见第 4.5 节）
4. 时间对齐完成后，根据设置执行不同的初始化：
   - 静态初始化
   - 动态初始化 - 速度矢量初始化
   - 动态初始化 - 位移矢量初始化
   - 配置设定初始化（SETTING）
5. **动态初始化默认模式选择**（详见第 5.4 节）：
   - SPP 模式 → 默认使用速度矢量初始化（通过多普勒测速得到的速度）
   - RTK/RTD 模式 → 默认使用位置差分初始化
   - 动态初始化需要设置运动阈值
   - 动态模式下 GNSS 数据不提供速度值时，统一使用位置差分法
6. 完成 GNSS 定位数据初始化 INS 后，才开始准备机械编排、组合导航事宜
7. **初始化模式需要识别 reboot**：第一次初始化后，长时间没有 GNSS 观测时还要继续进行初始化，与数据对齐统一调度识别 reboot（详见第 13 节）
8. **位置差分初始化的 GNSS 历元缓冲**：采用位置差分初始化方法时，需维护一个长度为 `gnss_buffer_size`（默认 3）的 GNSS 历元滑动窗口；当运动阈值达到时，确保缓冲区已存满 3 个历元，但**只用最新的两个历元位置解**计算位置差分速度（详见第 9.3 节）

**初始化调整要求**（来自 `skills/初始化调整.md`，本项目当前实现基准）：
9. **初始化准则**：状态初始化重要的是位置和速度，**一般姿态的初始化仅考虑偏航角，其他姿态角设为 0**
10. **静态初始化分高/低精度模式**（配置项 `high_precision_ins_mode`）：
    - 高精度模式：加速度计调平确定俯仰/横滚角，陀螺仪寻北确定偏航角（**本项目暂不实现**）
    - 低精度模式（**本项目当前实现**）：仅通过历史平均 GNSS 定位结果初始化位置，速度置 0，姿态角全设为 0，**不进行后续机械编排**，等到满足动态阈值时再进行动态初始化确定速度和偏航角
11. **动态初始化姿态简化**：偏航角通过东向速度和北向速度确定（`yaw = atan2(v_E, v_N)`），**其他姿态角设为 0**（不计算 pitch）
12. **IMU 误差标定**：一般只初始化加速度计和陀螺零偏，本项目当前 config 值置 0 依赖 EKF 在线估计，但保留从 config 读取的接口；同时预留 `_calibrate_bias_from_static_imu` 静态标定接口供后续优化

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **GNSS 主导** | 初始位置/速度优先使用 GNSS 解算结果，姿态由对准过程或配置确定 |
| **姿态仅偏航角** | 状态初始化重要的是位置和速度；**一般姿态的初始化仅考虑偏航角，其他姿态角设为 0**（来自初始化调整.md） |
| **IMU 辅助对准** | 仅高精度模式用加速度计调平+陀螺寻北；低精度模式不用 IMU 做姿态对准 |
| **配置优先级最高** | `use_set_posvelatt` 或 `use_set_attitude` 启用时，直接使用配置值，跳过自动对准 |
| **时间对齐先于对准** | 必须先将 IMU 数据线性插值到 GNSS 时间戳，再做对准计算，保证时间一致性 |
| **包夹条件强制** | GNSS 时间戳前后必须各有一个 IMU 历元（包夹区间）；不满足时延迟初始化，等待更多 IMU 数据 |
| **GNSS 模式决定动对准方式** | SPP 默认速度矢量初始化（多普勒测速），RTK/RTD 默认位置差分初始化；GNSS 不提供速度时统一用位置差分 |
| **位置差分需历元缓冲** | 位置差分初始化需维护 `gnss_buffer_size`（默认 3）长度的 GNSS 历元滑动窗口；运动阈值达到时确保缓冲区存满 3 个历元，但只用最新两个历元计算差分速度 |
| **坐标系统一** | 全部在 E 系（ECEF）下进行，对准过程中产生的 n 系中间量立即转回 E 系 |
| **单滤波协方差统一** | 单一 P 矩阵统一装配初始协方差（StateIndex 参数块），互不影响 |
| **Reboot 可重入** | 初始化可重复触发：长时间 GNSS 中断后识别 reboot，重新进入初始化流程；与 `Aligner` 的 reboot 调度统一识别 |
| **失败可降级** | 自动对准失败时，可降级为配置设定模式或继续等待数据 |

### 1.3 与现有模块的关系

```
AlignedBlock (来自 Aligner)               ← 路径 C 数据对齐管线输出
   ├── gnss: GnssSolution (timestamp, pos, vel, cov, mode)
   └── imu_list: List[ImuMeasurement]
                    ↓
            InsInitializer.initialize()
                    ↓
   ┌────────────────────────────────────┐
   │ 1. IMU 时间对齐到 GNSS 时间戳        │
   │ 2. 模式选择 (SETTING/静态/动态)     │
   │ 3. 对准计算 (姿态/位置/速度)        │
   │ 4. 装配初始状态                     │
   │ 5. 装配初始协方差 P                 │
   └────────────────────────────────────┘
                    ↓
            InsState (初始状态)
                    ↓
       进入 LcIntegration 机械编排循环
```

初始化模块位于数据对齐管线（`Aligner`）与 EKF 融合估计器（`LcIntegration`）之间：
- **上游**：`Aligner.harvest()` 输出的 `AlignedBlock`（含 GNSS 解 + 一个 GNSS 历元窗口内的 IMU 列表）
- **下游**：`LcIntegration.process_epoch()` 接收初始化完成的 `InsState`，进入机械编排 + EKF 主循环

## 3. 初始化触发条件

### 3.1 触发条件

`LcIntegration` 启动后处于 `UNINITIALIZED` 状态，从 `estimate_queue` 消费 `AlignedBlock`。当满足以下条件时触发初始化：

1. **首次匹配到 GNSS 数据**：`AlignedBlock.gnss` 不为 `None`，且 `GnssSolution.mode` 为有效解（`SPP`/`RTD`/`RTK_FIXED`/`RTK_FLOAT`/`External`）
2. **IMU 数据已积攒**：`AlignedBlock.imu_list` 至少包含 1 个 `ImuMeasurement`
3. **配置就绪**：初始化相关配置（`alignnment_posvelatt_mode`、`alignnment_attitude_mode`、`static_speed_threshold`、`dynamic_speed_threshold`、`angular_velocity_threshold_deg` 等）已加载

### 3.2 数据来源

| 数据 | 字段 | 来源 |
|------|------|------|
| GNSS 位置 | `gnss.pos` (ECEF, m) | `GnssSolution.pos`（来自 `InternalGnssSensor` 内部解算或外部文件） |
| GNSS 速度 | `gnss.vel` (ECEF, m/s) | `GnssSolution.vel`（同上；若 GNSS 仅有位置，则由位移差分计算，见第 9 节） |
| GNSS 协方差 | `gnss.cov` | `GnssSolution.cov`（用于初始位置/速度协方差） |
| GNSS 时间戳 | `gnss.timestamp` (Unix 秒) | `GnssSolution.timestamp` |
| IMU 列表 | `imu_list` (List[ImuMeasurement]) | `AlignedBlock.imu_list`（一个 GNSS 收割窗口内的 IMU 数据） |
| IMU 时间戳 | `imu.timestamp` (Unix 秒) | `ImuMeasurement.timestamp` |
| IMU 角速度 | `imu.gyro` (rad/s, b 系) | `ImuMeasurement.gyro` |
| IMU 加速度 | `imu.accel` (m/s², b 系) | `ImuMeasurement.accel` |

### 3.3 触发后的处理顺序

```
InsInitializer.initialize(aligned_block, config) -> InsState:

  1. 提取 GNSS 数据 + IMU 列表
  2. 【第 4 节】IMU 数据时间对齐到 GNSS 时间戳
     - 查找包夹 GNSS 时刻的前后 IMU 历元并做线性插值
  3. 【第 5 节】根据配置选择初始化模式
  4. 【第 6-10 节】执行对应模式的对准计算
     - SETTING: 直接读取配置
     - 静态: AcceLeveling + GNSS 位置
     - 动态-速度矢量: MotionAligned (GNSS 速度)
     - 动态-位移矢量: InterpolateGnssVel + MotionAligned
     - STATIONARY_AND_MOTION: 监测速度阈值，超限后切换
  5. 【第 11 节】装配初始状态 (位置/速度/姿态/IMU误差)
  6. 【第 12 节】装配初始协方差 P
  7. 返回 InsState，进入机械编排主循环
```

## 4. IMU 时间对齐到 GNSS 时间戳（线性插值）

> **核心要求**（用户原话）：初始化时当匹配到了 GNSS 数据，需要将 IMU 数据对齐到 GNSS 观测数据的时间戳。
>
> **当前策略**：本项目使用速率式 IMU（gyro/accel），在包夹 GNSS 时刻的前后 IMU 历元之间进行反距离加权线性插值。增量式 IMU 的切分方法仅作为参考，不直接用于本项目。
>
> 本节与 [imu.md 第 5 节](file:///home/mxl/workplace/gipylib/skills/imu.md#5-imugnss-插值与时间对齐) 描述的时间对齐方法**完全一致**。

### 4.1 问题背景

GNSS 解算历元（1 Hz）与 IMU 采样历元（100~200 Hz）通常不对齐。当 GNSS 量测时刻 `t_gnss` 落在两个 IMU 时刻 `t0` 和 `t2` 之间时，需要确定使用哪个 IMU 历元作为 `t_gnss` 时刻的代表性测量，保证对准计算时使用时间一致的 IMU/GNSS 数据。

### 4.2 调查结论：参考项目均使用增量式 IMU

#### 4.2.1 GINav 也使用增量式 IMU 且初始化无时间插值

[tools/GINav](file:///home/mxl/workplace/gipylib/tools/GINav) 是 MATLAB 项目，使用增量式 IMU（`imu.dw` / `imu.dv`）：

- [ins_init.m](file:///home/mxl/workplace/gipylib/tools/GINav/src/ins/ins_init.m) 直接接收 `avp0`，**初始化时无 IMU 时间插值**
- [ins_mech.m:18-19](file:///home/mxl/workplace/gipylib/tools/GINav/src/ins/ins_mech.m) `dw0 = imu.dw'` / `dv0 = imu.dv'` — 增量式 IMU 数据
- [gnss_ins_lc.m](file:///home/mxl/workplace/gipylib/tools/GINav/src/gnss_ins_lc/gnss_ins_lc.m) LC 量测更新直接使用当前 `ins.pos` / `ins.vel`，**无 IMU/GNSS 时间对齐**

**结论**：GINav 也没有精细化的初始化时间对齐方案。

#### 4.2.2 KF-GINS 同样使用增量式 IMU

### 4.3 本项目策略：GNSS 时刻线性插值

本项目对速率式 IMU 采用**线性插值**策略：

**核心思想**：在包夹 `t_gnss` 的两个 IMU 历元中，按目标时刻到两端的时间比例计算 gyro/accel，生成 timestamp 等于 `t_gnss` 的新 IMU 测量。

```
IMU 时间线:  t0 ----------- t2
                  ↑
GNSS 历元:   t_gnss (t0 < t_gnss < t2)

插值:
  dt1 = t_gnss - t0
  dt2 = t2 - t_gnss
  w0 = dt2 / (dt1 + dt2)
  w2 = dt1 / (dt1 + dt2)
  accel = w0 * imu_pre.accel + w2 * imu_cur.accel
  gyro  = w0 * imu_pre.gyro  + w2 * imu_cur.gyro
```

插值结果的 timestamp 精确设置为 `t_gnss`，因此 GNSS 融合时不再引入最近邻的半采样周期时间偏差。

### 4.4 实现接口（src/core/ins/interpolator.py）

| 函数 | 职责 |
|------|------|
| `find_bracket_imus(imu_list, t_gnss)` | 查找满足 `t_pre <= t_gnss <= t_cur` 的前后 IMU 历元 |
| `imu_interpolate_linear(imu_pre, imu_cur, t_gnss)` | 对 gyro/accel 做反距离加权线性插值，返回 timestamp 为 `t_gnss` 的 IMU 历元 |

**包夹条件**：

| 情况 | 条件 | 处理 |
|------|------|------|
| 0 | `t_gnss` 不在 `[t0, t2]` 之间 | 不满足包夹条件，延迟初始化 |
| 满足 | `t_pre <= t_gnss <= t_cur` | 执行线性插值 |
| 不满足 | GNSS 超出 IMU 缓冲区或缺少一侧历元 | 保留 GNSS 在 pending，等待后续 IMU |

> **注意**：`imu_interpolate` 仅为历史最近邻接口保留；当前代码路径统一调用 `imu_interpolate_linear`。

### 4.5 初始化阶段的包夹规则（强制要求）

> **用户原话**：插值时 GNSS 时间戳之前要有 IMU 数据，后面也要有一个 IMU 数据，除非刚好一致。

**强制约束**：初始化阶段执行 IMU 时间对齐时，必须满足**包夹条件**，否则**延迟初始化**，继续等待更多 IMU 数据：

| 条件 | 说明 | 处理方式 |
|------|------|---------|
| **包夹条件满足** |存在 `imu_pre.timestamp ≤ t_gnss ≤ imu_cur.timestamp` | 对前后历元执行线性插值 |
| **包夹条件不满足** | `t_gnss` 不在任一相邻 IMU 历元区间内，或仅一侧有 IMU 数据 | **延迟初始化**，等待更多 IMU 历元 |

**含义**：
- **GNSS 时间戳之前必须有 IMU 数据**：存在 `imu_pre` 且 `imu_pre.timestamp ≤ t_gnss`
- **GNSS 时间戳之后必须有 IMU 数据**：存在 `imu_cur` 且 `imu_cur.timestamp ≥ t_gnss`
- **包夹区间**：`imu_pre.timestamp ≤ t_gnss ≤ imu_cur.timestamp`

**为什么必须前后包夹**：
1. **线性插值的前提**：需要在 `t_gnss` 前后各有一个 IMU 历元，才能计算时间比例
2. **机械编排连续性**：初始化完成后立即进入机械编排，第一个 `dt` 由相邻 IMU 时间戳差计算；若前后 IMU 历元缺失，无法启动机械编排
3. **AcceLeveling 时间平均**：静态对准需要 `t_gnss` 前后一段时间的 IMU 数据做平均，仅一侧数据不足以反映静态状态

**实现策略**（`InsInitializer._align_imu_to_gnss`）：
```
function _align_imu_to_gnss(imu_list, t_gnss) -> ImuMeasurement or None:

  # 1. 寻找包夹区间 (find_bracket_imus)
  bracket = find_bracket_imus(imu_list, t_gnss)
  if bracket is None:
      return None  # 不满足包夹条件，延迟初始化

  # 2. 线性插值 (imu_interpolate_linear)
  imu_pre, imu_cur, _ = bracket
  return imu_interpolate_linear(imu_pre, imu_cur, t_gnss)
    # accel/gyro 按前后历元时间比例加权，timestamp = t_gnss

# 调用方 (InsInitializer.initialize)
interp_imu = self._align_imu_to_gnss(imu_list, gnss.timestamp)
if interp_imu is None:
    raise ValueError("IMU 数据不满足包夹条件")
```

### 4.6 时间对齐误差与 KF 估计（预留接口）

线性插值将融合边界精确放置在 GNSS 时间戳；时间偏差状态扩展仍作为后续模型预留：

- **状态扩维**：在 EKF 15 维状态 `[δr^e, δv^e, δφ^e, δb_g, δb_a]` 基础上扩展为 16 维，新增 `δt`（时间对齐误差）
- **观测模型**：时间误差通过 IMU 采样时刻与 GNSS 时刻的偏差耦合到位置/速度量测
- **当前状态**：仅作为预留接口文档化，实际 KF 实现详见 [estimator.md](file:///home/mxl/workplace/gipylib/skills/estimator.md)

### 4.7 注意事项

- **插值不修改原始 IMU 历元**：`imu_pre` 和 `imu_cur` 保持不变，仅生成新的 `ImuMeasurement`（timestamp 标记为 `t_gnss`，数据为线性插值）
- **统一插值路径**：初始化、LC 和 TC 主循环均使用相同的 `imu_interpolate_linear` 实现
- **边界处理**：当 GNSS 历元超出 IMU 缓冲区范围时，不满足包夹条件，延迟初始化
- 初始化阶段时间对齐完成后，对准计算使用 GNSS 时刻的插值 IMU；后续机械编排从包夹区间的当前历元继续，维护 `imupre`/`imucur` 关系

### 4.8 LC/TC 主循环中的融合边界

正常运行时，GNSS 到达后先进入 `pending` 队列，等待后续 IMU 将时间区间包夹。处理顺序固定为：

1. 在前后 IMU 历元之间线性插值到 `t_gnss`；
2. 传播 INS 状态到 `t_gnss`；
3. 在 GNSS 时刻执行 LC 或 TC 融合；
4. 立即输出该时刻的融合状态（Qins=3）；
5. 再使用当前 IMU 继续传播到其原始时间戳，输出普通 IMU 状态（Qins=2）。

若 `t_gnss` 晚于当前 IMU，保留 pending；若恰好等于前一历元时间，不重复传播。原始 IMU 历元始终不被修改。

### 5.4 动态初始化默认模式选择（基于 GNSS 解算模式）

> **用户原话**：如果进行动态初始化（当为 spp 模式时，默认使用速度矢量（通过多普勒测速得到的速度）初始化；为 rtk/rtd 模式时，默认使用位置差分初始化；动态初始化需要设置运动阈值）；当动态模式下，GNSS 数据不提供速度值时，统一使用位置差分法。

#### 5.4.1 默认规则

动态初始化（`IN_MOTION` 模式）下，根据 GNSS 解算模式自动选择初始化方法：

| GNSS 解算模式 | 默认动对准方法 | 速度来源 | 原因 |
|--------------|--------------|---------|------|
| **SPP** | 速度矢量初始化（第 8 节 MotionAligned） | 多普勒测速 `sol.vel` | SPP 位置精度差（~10m），位置差分得到的速度不可信；多普勒测速直接基于载波观测，精度独立于位置精度 |
| **RTK Fixed / RTK Float** | 位置差分初始化（第 9 节 InterpolateGnssVel） | 相邻历元位置差分 | RTK 位置精度高（~0.02-0.1m），位置差分速度精度优于多普勒；且 RTK 在低速场景多普勒可能受周跳影响 |
| **RTD** | 位置差分初始化（第 9 节 InterpolateGnssVel） | 相邻历元位置差分 | RTD 位置精度优于 SPP（~1m），位置差分速度可用 |
| **External** | 按 `gnss_velocity_fallback` 配置 | 配置决定 | 外部数据源情况复杂，由用户配置 |

|-------------------------------|------|
| `"auto"`（默认） | 按 GNSS 解算模式自动选择（上表） |

| `"position_diff"` | 强制使用位置差分初始化（第 9 节） |

#### 5.4.2 GNSS 不提供速度时的统一回退策略

> **用户原话**：当动态模式下，GNSS 数据不提供速度值时，统一使用位置差分法。

无论 GNSS 解算模式如何（SPP / RTK / RTD），只要 `GnssSolution.vel` 为 `None` 或无效，**统一使用位置差分法**（第 9 节 InterpolateGnssVel）。位置差分需维护 `gnss_buffer_size`（默认 3）长度的 GNSS 历元滑动窗口，但**只用最新的两个历元**计算差分速度：

```
function resolve_gnss_velocity(gnss, gnss_buffer, config) -> vel_ecef:

  # 1. 检查 GNSS 是否直接提供速度
  if gnss.vel is not None and is_valid(gnss.vel):
    return gnss.vel  # 直接使用 GNSS 速度

  # 2. GNSS 不提供速度，统一使用位置差分法
  #    将当前历元加入缓冲区（维护 gnss_buffer_size 长度的滑动窗口）
  gnss_buffer.append(gnss)
  if len(gnss_buffer) > config.gnss_buffer_size:
    gnss_buffer.pop(0)  # 移除最旧的

  # 3. 缓冲区不足两个历元，无法差分
  if len(gnss_buffer) < 2:
    return None  # 继续等待

  # 4. 只用最新的两个历元计算位置差分速度
  prev_gnss = gnss_buffer[-2]  # 倒数第二个（最新前一个）
  curr_gnss = gnss_buffer[-1]  # 最新一个
  dt = curr_gnss.timestamp - prev_gnss.timestamp
  if dt <= 0:
    return None  # 时间戳异常
  return (curr_gnss.pos - prev_gnss.pos) / dt
```

**注意**：
- 位置差分需要两个相邻 GNSS 历元，第一个 GNSS 历元到达时无法差分，需继续等待第二个
- **GNSS 历元缓冲区**：`gnss_buffer` 维护 `gnss_buffer_size`（默认 3）个历元的滑动窗口，提供历史冗余；但差分计算**只用最新两个历元**，保证速度反映最新运动状态
- SPP 模式下若 GNSS 不提供速度，仍使用位置差分（虽有精度损失，但保证流程可继续）
- 位置差分速度的协方差由位置协方差传播：`vel_cov = (pos_cov1 + pos_cov2) / dt²`

#### 5.4.3 三组独立阈值（static_speed / dynamic_speed / angular_velocity）

> **用户原话**：静态检测的阈值是 0.5m/s，但是动态初始化需要角速度的范数需要小于 (30.0×(π/180.0)) rad/s，差分速度和直接计算的速度范数需要大于 4m/s。

**作用**：判定车辆是否处于运动状态、是否可进入动对准。本项目采用**三组独立阈值**替代单一 `motion_threshold`，分别约束静态检测、动态速度、动态角速度。

**配置项**（`data/config.yaml` 的 `ins` 段）：

| 配置项 | 类型 | 默认值 | 含义 |
|--------|------|--------|------|
| `static_speed_threshold` | double | 0.5 | **静态检测速度阈值** (m/s)：GNSS 速度范数 < 此值判定为静态，进入静对准 |
| `dynamic_speed_threshold` | double | 4.0 | **动态速度阈值** (m/s)：GNSS 速度范数 > 此值才可进入动对准（适用于速度矢量法与位置差分法） |
| `angular_velocity_threshold_deg` | double | 30.0 | **动态角速度阈值** (deg/s)：陀螺角速度范数 < 此值才可进入动对准（≈0.5236 rad/s） |
| `motion_threshold` | double | 0.5 | **已废弃**（保留兼容），由上述三阈值替代 |

**判定逻辑**（实际实现于 `InsInitializer.initialize()`）：

```
function check_init_thresholds(gnss, imu_list, mode) -> bool:

  speed = norm(gnss.vel_ecef)  # GNSS 速度范数

  # 1. 静态模式: 速度必须 < static_speed_threshold
  if mode == STATIC:
    if speed >= config.static_speed_threshold:
      raise ValueError("静态初始化要求速度 < static_speed_threshold")
    return True

  # 2. 动态模式 (VELOCITY_VECTOR / POSITION_DIFF):
  #    2a. 速度必须 > dynamic_speed_threshold
  if speed <= config.dynamic_speed_threshold:
    raise ValueError("动态初始化要求速度 > dynamic_speed_threshold")

  #    2b. 陀螺角速度范数必须 < angular_velocity_threshold
  gyro_norm = compute_gyro_norm(imu_list, gnss.timestamp, window=1.0)
  if gyro_norm >= config.angular_velocity_threshold:
    raise ValueError("动态初始化要求角速度 < angular_velocity_threshold")

  return True
```

**陀螺角速度范数计算**（`_compute_gyro_norm()` 方法）：

```
function compute_gyro_norm(imu_list, t_gnss, window=1.0) -> float:

  # 取 GNSS 时间戳前后 ±1s 窗口内的 IMU 历元
  t_start = t_gnss - window
  t_end = t_gnss + window
  window_imus = [imu for imu in imu_list if t_start <= imu.timestamp <= t_end]

  if not window_imus:
    window_imus = list(imu_list)  # 窗口为空时使用全部 IMU 数据
  if not window_imus:
    return float('inf')  # 无 IMU 数据时不允许动对准

  # 计算窗口内陀螺角速度范数的平均值
  gyro_norms = [norm(imu.gyro) for imu in window_imus]
  return mean(gyro_norms)
```

**阈值选择建议**：

| 场景 | `static_speed_threshold` | `dynamic_speed_threshold` | `angular_velocity_threshold_deg` | 原因 |
|------|--------------------------|---------------------------|----------------------------------|------|
| 默认（车辆） | 0.5 m/s | 4.0 m/s | 30.0 deg/s | 区分静止与低速行驶；角速度约束避免转弯时初始化 |
| 行人/低速车辆 | 0.2 m/s | 1.0 m/s | 20.0 deg/s | 避免低速被误判为静止 |
| 高速车辆 | 1.0 m/s | 5.0 m/s | 30.0 deg/s | 避免停车等红灯时误判为运动 |
| 严格静态启动 | 0.1 m/s | — | — | 仅在确实静止时进入静对准 |

**注意**：
- 三组阈值相互独立，分别约束不同维度
- `static_speed_threshold` 用于静对准（速度必须低于此值）
- `dynamic_speed_threshold` 用于动对准（速度必须高于此值）
- `angular_velocity_threshold_deg` 仅用于动对准（陀螺范数必须低于此值），避免在车辆转弯等高角速度场景下初始化
- 阈值过低会导致 GNSS 速度噪声（SPP 多普勒噪声 ~0.1 m/s）触发误判
- `motion_threshold` 字段保留兼容性，但 `InsInitializer` 不再读取，仅由历史配置文件兼容

## 6. 配置设定初始化（SETTING）

### 6.1 触发条件

配置设定模式有两种子模式：

1. **`use_set_posvelatt = 1`**：完整 PVA（位置/速度/姿态）均来自配置文件
   - 直接使用配置的 `initial_pos` / `initial_vel` / `initial_att`
   - **不消费 GNSS 数据流**（跳过 GNSS 等待）
   - 时间戳取配置的起始时间（`GetStartAndEndTime` 的 `start_time`）
   - 协方差使用固定小值（`pos_std=[0.1,0.1,0.1]`, `vel_std=[0.01,0.01,0.01]`, `att_std=[0.01,0.01,0.01]`）

2. **`use_set_attitude = 1`**：仅姿态来自配置，位置/速度来自 GNSS
   - 等待第一个 GNSS 历元
   - 位置/速度取自 GNSS 解算结果
   - 姿态取自配置的 `initial_att`
   - 协方差：位置/速度使用 GNSS 解算的协方差，姿态使用配置的 `initial_att_std`

### 6.2 处理流程（伪代码）

```
function align_setting(aligned_block, config) -> InsState:

  if config.use_set_posvelatt:
    # 完整配置模式
    pos_llh = config.initial_pos              # [lat, lon, h] (度/度/米)
    vel_ned = config.initial_vel              # [vN, vE, vD] (m/s)
    att_rpy = config.initial_att * deg2rad    # [roll, pitch, yaw] (rad)
    timestamp = config.start_time             # Unix 秒

    # 协方差使用固定小值
    pos_std = [0.1, 0.1, 0.1]
    vel_std = [0.01, 0.01, 0.01]
    att_std = [0.01, 0.01, 0.01]

  elif config.use_set_attitude:
    # 仅姿态配置模式
    gnss = aligned_block.gnss
    pos_ecef = gnss.pos                       # ECEF (m)
    vel_ecef = gnss.vel                       # ECEF (m/s)
    pos_llh = ecef2llh(pos_ecef)              # 转换为纬经高
    vel_ned = C_e^n @ vel_ecef                # 转换为 NED
    att_rpy = config.initial_att * deg2rad
    timestamp = gnss.timestamp

    # 协方差使用 GNSS 解算的协方差
    pos_std = sqrt(diag(gnss.cov[0:3,0:3]))
    vel_std = sqrt(diag(gnss.cov[3:6,3:6]))
    att_std = config.initial_att_std * deg2rad

  # n 系 PVA → E 系 PVA（参考 att_caln2e）
  C_n_e = CalCe2n(pos_llh.lat, pos_llh.lon).T  # n→e 旋转矩阵
  C_b_n = euler2dcm(att_rpy)                    # b→n 旋转矩阵
  C_b_e = C_n_e @ C_b_n                         # b→e 旋转矩阵
  vel_e = C_b_n.T @ vel_ned  或  C_e^n.T @ vel_ned
         # 用 C_b_n 转换速度，注意 att 表示车体姿态，需根据实际定义确认
  pos_e = llh2ecef(pos_llh)

  return InsState(timestamp, pos_e, vel_e, C_b_e, att_rpy, pos_std, vel_std, att_std)
```

### 6.3 适用场景

- **已知初始状态**：车辆静态启动且已知精确位置/姿态（如基站、静态测试）
- **测试与调试**：跳过自动对准，快速进入机械编排阶段
- **IMU 故障恢复**：IMU 数据中断后重新启动，使用上次已知状态作为初值

### 6.4 注意事项

- `use_set_posvelatt = 1` 模式下，本项目指导方案建议位置/速度遵循配置值（更符合"配置设定"语义）
- 配置的位置/速度单位需明确：本项目约定位置为 LLH（纬度/经度/高程），速度为 NED（北/东/下），姿态为 RPY（横滚/俯仰/航向），与 KF-GINS 一致
- 协方差使用固定小值意味着对配置值高度信任，仅在配置值确实精确时使用

## 7. 静态初始化

### 7.0 高/低精度模式选择（来自初始化调整.md）

> **用户原话**：静态初始化对陀螺仪的要求较高，需要在配置文件里设置是否是高精度惯性导航模式。如果是则通过加速度计调平确定俯仰角和横滚角，通过陀螺仪寻北确定偏航角；如果不是仅通过历史平均GNSS定位结果初始化维护位置，速度置为0，姿态角设为0，不进行后续的机械编排，等到满足动态阈值时，再进行动态初始化确定速度和偏航角。**本项目暂时实现低精度的INS初始化**。

通过配置项 `high_precision_ins_mode`（bool, 默认 `false`）选择：

| 模式 | `high_precision_ins_mode` | 姿态对准方法 | 位置 | 速度 | 机械编排 | 实现状态 |
|------|--------------------------|------------|------|------|---------|---------|
| **高精度** | true | AcceLeveling（roll/pitch）+ 陀螺寻北（yaw） | GNSS | 0 | 可进入 | 🚧 暂不实现 |
| **低精度**（本项目当前） | false | **不做姿态对准，att=[0,0,0]** | GNSS 历史平均 | 0 | **不进入**，等动态阈值 | ✅ 已实现 |

### 7.1 触发条件

当**首次 GNSS 速度 < `static_speed_threshold`** 且**未启用配置设定模式**时，进入静态初始化。

### 7.2 低精度模式（本项目当前实现）

**核心策略**（来自初始化调整.md）：
1. **位置**：GNSS 历史平均（`static_duration` 秒窗口，少于 10s 用全部，多于 10s 取最新 10s）
2. **速度**：置 0
3. **姿态**：`[roll=0, pitch=0, yaw=0]`
4. **不做 AcceLeveling，不做机械编排**
5. **持续监测**：等速度超 `dynamic_speed_threshold` 后切换到动态初始化（第 8/9 节）确定速度和偏航角

**GNSS 位置平均策略**（用户确认）：
- 维护一个 GNSS 位置缓冲区（`static_duration` 秒滑动窗口）
- 少于 10 秒时使用全部可用 GNSS 历元的平均
- 多于 10 秒时固定取最新 10 秒内的 GNSS 历元平均

### 7.3 低精度模式处理流程（伪代码）

```python
function align_static_low_precision(gnss_buffer, config) -> InsState:

  # 1. GNSS 位置平均（static_duration 秒窗口）
  static_duration = config.get("static_duration", 10.0)
  t_now = gnss_buffer[-1].timestamp
  t_start = t_now - static_duration
  window_gnss = [g for g in gnss_buffer if g.timestamp >= t_start]
  if not window_gnss:
    window_gnss = list(gnss_buffer)  # 少于 10s 用全部
  pos_e = mean([g.position for g in window_gnss], axis=0)

  # 2. 速度置 0
  vel_e = np.zeros(3)

  # 3. 姿态全设为 0（不做 AcceLeveling）
  att_rpy = np.array([0.0, 0.0, 0.0])  # roll=0, pitch=0, yaw=0

  # 4. 转换到 E 系
  lat, lon, _ = ecef2llh(pos_e)
  C_b_n = euler2dcm(att_rpy)
  C_b_e = att_caln2e(lat, lon, C_b_n)

  # 5. 返回"待定"状态（不进入机械编排，等动态阈值）
  return InsState(timestamp, pos_e, vel_e, C_b_e, att_rpy, ...)
  # 调用方继续监测，速度超 dynamic_speed_threshold 后调用动态初始化
```

### 7.4 高精度模式（预留，暂不实现）

高精度模式采用加速度计调平确定 roll/pitch，算法流程（伪代码，仅指导）：

```
function acce_leveling(imu_buffer) -> Euler:

  # 1. 对静态 IMU 缓冲区做时间平均，得到平均比力 f_b
  f_b = mean(imu.acce for imu in imu_buffer) / dt   # 平均比力

  # 2. 由重力方向反解姿态角（假设静止，f_b ≈ -g 方向）
  roll  = asin(f_b[1] / g0) * sign(f_b[2])
  pitch = asin(f_b[0] / g0) * (-sign(f_b[2]))
  return Euler(roll, pitch, 0)
```

- **roll/pitch**：加速度计调平（AcceLeveling）
- **yaw**：陀螺仪寻北（高精度 IMU 感知地球自转）
- **本项目 MEMS IMU 无法感知地球自转**，故高精度模式暂不实现

### 7.5 适用场景

- **低精度模式**：MEMS IMU 车载场景，静止启动后等车辆起步再做动态初始化（最常见）
- **高精度模式**：战术级以上 IMU，需精确初始姿态（预留）

### 7.6 注意事项

- **低精度模式不做 AcceLeveling**：姿态全设为 0，依赖后续动态初始化确定偏航角
- **GNSS 位置平均**：少 10s 用全部，多 10s 取最新 10s，避免陈旧数据污染
- **不进入机械编排**：低精度静态初始化返回的状态仅记录位置，等动态阈值后才真正完成初始化

## 8. 动态初始化 - 速度矢量初始化

### 8.1 触发条件

当**首次 GNSS 速度 > `velocity_threshold`** 且**未启用配置设定模式**时，进入动态初始化-速度矢量模式。

### 8.2 MotionAligned 算法（本项目简化版）

`motion_aligned` 算法流程（由 GNSS 速度计算初始航向）：

```
function motion_aligned(gnss_data) -> (pos, vel, att):

  pos = gnss_data.pos
  vel = gnss_data.vel
  blh = WGS84XYZ2BLH(pos)                      # ECEF → LLH
  vel_ned = CalCe2n(blh.lat, blh.lon) @ vel    # ECEF 速度 → NED 速度
  att = [0.0,                                  # roll = 0
         atan2(-vel_ned[2], sqrt(vel_ned[0]^2 + vel_ned[1]^2)),  # pitch
         atan2(vel_ned[1], vel_ned[0])]        # yaw
  return pos, vel, att
```

**本项目简化**（来自初始化调整.md：偏航角通过东向/北向速度确定，其他姿态角设为 0）：
- **本项目不计算 pitch**，直接设 `pitch = 0`，仅保留 `yaw = atan2(v_E, v_N)`

**数学原理**（本项目简化版）：

车辆运动时，假设车辆在水平面运动且无侧滑，则：
- **航向角（yaw）**：由 GNSS 速度方向确定，`yaw = atan2(v_E, v_N)`（NED 速度的东向/北向分量）
- **俯仰角（pitch）**：**设为 0**（初始化调整.md 要求其他姿态角设为 0）
- **横滚角（roll）**：**设为 0**

```
yaw   = atan2(v_E, v_N)
pitch = 0
roll  = 0
```

其中 `v_N`, `v_E`, `v_D` 为 GNSS 速度在 NED 坐标系下的分量，由 ECEF 速度转换得到：
```
v_ned = C_e^n @ v_ecef
```

### 8.3 处理流程（伪代码）

```python
function align_motion_velocity(gnss, config) -> (att_rpy, vel_e):

  vel_e = gnss.velocity.copy()
  pos_e = gnss.position

  # 1. 转换为 LLH（用于构造 C_e^n）
  lat, lon, _ = ecef2llh(pos_e)

  # 2. ECEF 速度 → NED 速度
  C_e_n = cal_Ce2n(lat, lon)                       # e→n 旋转矩阵
  vel_ned = C_e_n @ vel_e                          # [v_N, v_E, v_D]

  # 3. 计算姿态（本项目简化：仅 yaw，其他=0）
  roll  = 0.0
  pitch = 0.0                                       # 不计算 pitch（初始化调整.md）
  yaw   = math.atan2(vel_ned[1], vel_ned[0])       # atan2(v_E, v_N)
  att_rpy = np.array([roll, pitch, yaw])

  return att_rpy, vel_e
```

### 8.4 适用场景

- 车辆起始即处于运动状态（如行驶中启动系统）
- 车载 GNSS/INS 系统，初始速度已知且大于阈值
- 不需要静态阶段，快速进入组合导航

### 8.5 注意事项

- **速度阈值**：`velocity_threshold` 默认 0.5 m/s，过低会导致航向角噪声大（低速时 GNSS 速度方向不稳定）
- **假设条件**：车辆水平运动、无侧滑、无侧倾。若实际工况不满足，初始姿态会有偏差，需依赖 EKF 收敛
- **GNSS 速度精度**：动对准精度直接依赖 GNSS 速度精度，建议使用 RTK 速度（精度 ~0.05 m/s）
- **车载设备坐标系差异**：面向车载设备，若设备坐标系与车体系差异不显著可忽略；若 IMU 安装角显著，需先做安装角补偿
- **atan2 参数顺序**：注意 `atan2(v_E, v_N)` 与 `atan2(y, x)` 的对应关系，避免航向角符号错误

## 9. 动态初始化 - 位移矢量初始化

### 9.1 触发条件

当**GNSS 数据源仅提供位置（无速度）**时（`gnss.format_type_ == GNSSPOS`），需要通过两个相邻 GNSS 历元的位置差分计算速度，再进入第 8 节的 MotionAligned 流程。

**GNSS 历元缓冲区要求**（用户原话）：采用位置差分初始化方法时，需维护一个长度为 `gnss_buffer_size`（默认 3）的 GNSS 历元滑动窗口。当运动阈值达到时，**确保缓冲区已存满 3 个历元**，但**只用最新的两个历元位置解**计算位置差分速度。若缓冲区未存满，延迟初始化继续等待。

### 9.2 InterpolateGnssVel 算法

`interpolate_gnss_vel` 算法流程（伪代码，仅指导）：

```
function interpolate_gnss_vel(first, second) -> GnssData:

  # 由两个相邻 GNSS 历元位置差分计算速度
  second.vel = (second.pos - first.pos) / (second.time - first.time)
  return second
```

**数学原理**：

```
v_ecef = (pos_ecef[t2] - pos_ecef[t1]) / (t2 - t1)
```

即用两个相邻 GNSS 历元的位置差除以时间差，得到 ECEF 速度。

### 9.3 处理流程（伪代码）

> **核心约束**（用户原话）：采用位置差分初始化方法时，确保要存储之前几个历元的 GNSS 位置解，即确保当前运动阈值要达到的同时，设置为要存储 3 个历元的 GNSS 定位解，但是只用最新的两个历元位置解来计算。

```
function align_motion_displacement(aligned_block, config, gnss_buffer) -> InsState:

  gnss = aligned_block.gnss

  # 1. 检查 GNSS 数据是否包含速度
  if gnss.vel is None or gnss.format_type == GNSSPOS:
    # 仅位置模式，需要 GNSS 历元缓冲区做差分

    # 1.1 将当前历元加入缓冲区（维护 gnss_buffer_size 长度的滑动窗口）
    gnss_buffer.append(gnss)
    if len(gnss_buffer) > config.gnss_buffer_size:  # 默认 3
      gnss_buffer.pop(0)  # 移除最旧的

    # 1.2 缓冲区不足，无法差分
    if len(gnss_buffer) < 2:
      return None  # 继续等待

    # 1.3 用最新的两个历元计算位置差分速度（参考 interpolate_gnss_vel）
    #     注意：即使缓冲区有 3 个历元，也只用最新的两个（gnss_buffer[-2] 和 gnss_buffer[-1]）
    prev_gnss = gnss_buffer[-2]  # 倒数第二个（最新前一个）
    curr_gnss = gnss_buffer[-1]  # 最新一个
    dt_gnss = curr_gnss.timestamp - prev_gnss.timestamp
    if dt_gnss <= 0:
      return None  # 时间戳异常

    vel_e = (curr_gnss.pos - prev_gnss.pos) / dt_gnss
    gnss.vel = vel_e  # 填充速度字段
    gnss.cov[3:6, 3:6] = (curr_gnss.cov[0:3, 0:3] + prev_gnss.cov[0:3, 0:3]) / dt_gnss^2
                        # 速度协方差由位置协方差传播

    # 1.4 检查动态速度阈值是否达到 AND 缓冲区是否存满
    if norm(vel_e) > config.dynamic_speed_threshold:
      if len(gnss_buffer) < config.gnss_buffer_size:
        # 速度阈值达到但缓冲区未存满（< 3 个历元），延迟初始化继续等待
        # 确保"速度阈值达到的同时，缓冲区已存满 3 个历元"
        return None
      # 速度阈值达到且缓冲区存满，继续执行后续对准

  # 2. 速度已就绪，进入速度矢量初始化（第 8 节）
  return align_motion_velocity(aligned_block, config)
```

**关键设计**：
- **缓冲区大小 3，计算只用 2**：`gnss_buffer` 维护 `gnss_buffer_size`（默认 3）个历元，提供历史冗余；但位置差分计算**只用最新的两个历元**（`gnss_buffer[-2]` 和 `gnss_buffer[-1]`），保证速度反映最新运动状态
- **双重门槛**：运动阈值达到 AND 缓冲区存满 3 个历元，两者同时满足才进入对准；任一不满足则延迟初始化
- **历史冗余的用途**：第 3 个历元（最旧的）可作为 fallback，当最新两个历元中有一个出现异常（如周跳、粗差）时，可回退使用 `gnss_buffer[-3]` 与 `gnss_buffer[-1]` 做差分

### 9.4 适用场景

- GNSS 解算结果仅输出位置（如 SPP 模式可能不输出速度）
- 外部 GNSS 文件仅包含位置信息（如某些 POS 文件格式）
- 验证 GNSS 速度精度（与差分速度对比）

### 9.5 注意事项

- **GNSS 历元缓冲区**（用户原话）：采用位置差分初始化方法时，需维护 `gnss_buffer_size`（默认 3）长度的 GNSS 历元滑动窗口；运动阈值达到时确保缓冲区已存满 3 个历元，但**只用最新的两个历元位置解**计算差分速度
- **需要两个 GNSS 历元**：第一个 GNSS 历元到达时无法计算速度，需继续等待第二个
- **时间间隔**：GNSS 采样率 1 Hz 时，差分时间间隔 1 秒，速度精度受位置精度限制（SPP ~10m 位置 → ~10 m/s 速度误差，不可用；RTK ~0.02m 位置 → ~0.02 m/s 速度误差，可用）
- **精度损失**：差分速度精度低于直接多普勒测速，建议优先使用 GNSS 直接输出的速度
- **加速度影响**：若车辆加速度较大，差分速度反映的是 `[t1, t2]` 区间内的平均速度，与 `t2` 时刻的瞬时速度有差异
- **本项目 GNSS 数据源**：`InternalGnssSensor` 输出的 `GnssSolution` 通常包含速度（来自 rtklib-py 的 `sol.rr[3:6]`），故此模式主要用于外部 GNSS 文件场景
- **缓冲区清空时机**：reboot 事件触发时需清空 `gnss_buffer`（详见第 13.6.4 节），避免使用 reboot 前的陈旧历元

## 10. 静止启动到动对准（STATIONARY_AND_MOTION）

### 10.1 触发条件

当**首次 GNSS 速度 < `static_speed_threshold`** 且**未启用配置设定模式**时，进入 `STATIONARY_AND_MOTION` 模式。

**低精度模式下的简化**（本项目当前实现）：
- 静止阶段：记录 GNSS 平均位置，vel=0，att=[0,0,0]（第 7 节低精度模式）
- 动态触发：速度超 `dynamic_speed_threshold` 后切换到动态初始化（第 8/9 节）
- **不做 AcceLeveling 融合**：本项目低精度模式直接用动态初始化（roll=0, pitch=0, yaw=atan2(v_E,v_N)），不做加速度计调平

### 10.2 监测逻辑（低精度模式简化版）

本项目低精度模式简化如下：

```python
# 低精度模式：静止记录位置 → 等动态阈值 → 动态初始化
while True:
    aligned_block = estimate_queue.get()

    # 1. 静止阶段：积累 GNSS 位置做平均（第 7.3 节）
    gnss_buffer.append(aligned_block.gnss)
    # 维护 static_duration 秒滑动窗口

    # 2. 检查动态速度阈值
    speed = norm(gnss.vel)
    if speed > dynamic_speed_threshold:
        # 3. 检查陀螺角速度阈值（第 5.4.3 节）
        gyro_norm = compute_gyro_norm(imu_list, gnss.timestamp)
        if gyro_norm < angular_velocity_threshold:
            # 4. 切换到动态初始化（第 8/9 节），不做 AcceLeveling
            att_rpy, vel_e = align_motion_velocity(gnss, config)
            # roll=0, pitch=0, yaw=atan2(v_E, v_N)
            return InsState(...)
    # 否则继续等待（静止阶段 att=[0,0,0]）
```

### 10.3 处理流程（伪代码）

```
function align_stationary_then_motion(initial_block, config) -> InsState:

  # 1. 进入 STATIONARY_AND_MOTION 模式
  imu_buffer = []  # 维护 data_rate * 10 长度的滑动窗口
  gnss_buffer = []  # 维护 gnss_buffer_size（默认 3）长度的 GNSS 历元滑动窗口

  # 2. 持续消费 estimate_queue，监测速度
  while True:
    aligned_block = estimate_queue.get()  # 等待下一个历元

    # 2.1 IMU 数据入缓冲区
    for imu in aligned_block.imu_list:
      imu_buffer.append(imu)
      if len(imu_buffer) > config.data_rate * 10:
        imu_buffer.pop(0)  # 维护滑动窗口

    # 2.2 处理 GNSS 数据
    gnss = aligned_block.gnss
    if gnss is None:
      continue

    # 2.3 仅位置模式，差分计算速度（第 9 节，使用 gnss_buffer）
    if gnss.format_type == GNSSPOS:
      # 2.3.1 将当前历元加入缓冲区（维护 gnss_buffer_size 长度的滑动窗口）
      gnss_buffer.append(gnss)
      if len(gnss_buffer) > config.gnss_buffer_size:
        gnss_buffer.pop(0)

      # 2.3.2 缓冲区不足两个历元，无法差分
      if len(gnss_buffer) < 2:
        continue

      # 2.3.3 只用最新的两个历元计算位置差分速度
      prev_gnss = gnss_buffer[-2]
      curr_gnss = gnss_buffer[-1]
      gnss.vel = (curr_gnss.pos - prev_gnss.pos) / (curr_gnss.timestamp - prev_gnss.timestamp)

    # 2.4 检查动态速度阈值 + 陀螺角速度阈值（第 5.4.3 节三阈值系统）
    if norm(gnss.vel) > config.dynamic_speed_threshold:
      # 速度超阈值，进一步检查陀螺角速度范数
      gyro_norm = compute_gyro_norm(imu_buffer, gnss.timestamp, window=1.0)
      if gyro_norm >= config.angular_velocity_threshold:
        # 角速度过大（车辆转弯等），延迟初始化继续等待
        continue

      # 角速度合格，检查缓冲区是否存满（第 9.3 节双重门槛）
      if gnss.format_type == GNSSPOS and len(gnss_buffer) < config.gnss_buffer_size:
        # 缓冲区未存满，延迟初始化继续等待
        continue

      # 速度与角速度均合格且缓冲区存满，切换到动对准

      # 2.4.1 MotionAligned 计算 yaw（第 8 节）
      pos_llh = ecef2llh(gnss.pos)
      C_e_n = CalCe2n(pos_llh.lat, pos_llh.lon)
      vel_ned = C_e_n @ gnss.vel
      yaw = atan2(vel_ned[1], vel_ned[0])  # 东向, 北向

      # 2.4.2 AcceLeveling 计算 roll/pitch（第 7 节）
      f_mean = average([imu.accel for imu in imu_buffer])
      g = 9.7803267715
      roll  = asin(f_mean[1] / g) * sign(f_mean[2])
      pitch = asin(f_mean[0] / g) * -sign(f_mean[2])

      # 2.4.3 融合：yaw 取自动对准，roll/pitch 取自加速度计
      att_rpy = [roll, pitch, yaw]

      # 2.4.4 转换到 E 系（参考 AttCaln2e）
      C_b_n = euler2dcm(att_rpy)
      C_n_e = C_e_n.T
      C_b_e = C_n_e @ C_b_n

      # 2.4.5 协方差（STATIONARY_AND_MOTION 默认值）
      pos_std = sqrt(diag(gnss.cov[0:3,0:3]))
      vel_std = sqrt(diag(gnss.cov[3:6,3:6]))
      att_std = [2.0_deg, 2.0_deg, 5.0_deg]  # roll/pitch 较准（静对准），yaw 较松（动对准）

      return InsState(gnss.timestamp, gnss.pos, gnss.vel, C_b_e, att_rpy, pos_std, vel_std, att_std)
```

### 10.4 适用场景

- 车辆静止启动，等待起步后完成对准（最常见场景）
- 不依赖配置航向值，全部由传感器观测确定
- 融合静对准（加速度计水平对准）与动对准（GNSS 速度航向）的优势

### 10.5 注意事项

- **IMU 缓冲区长度**：`data_rate * 10` 表示 10 秒滑动窗口，过长会引入运动数据污染，过短会降低平均精度
- **滑动窗口策略**：先进先出（FIFO），保证缓冲区始终包含最近的 10 秒数据
- **超阈值时刻的 IMU 数据**：触发动对准时，缓冲区可能已包含部分运动数据，影响 AcceLeveling 精度；建议在速度超阈值前一小段时间（如 1 秒）的数据用于 AcceLeveling
- **融合策略**：`roll/pitch` 取自 AcceLeveling（精度高），`yaw` 取自 MotionAligned（MEMS 静态无法确定航向）
- **超时处理**：若长时间速度未超阈值，可降级为纯静态初始化（第 7 节），使用配置航向

### 11.3 坐标系转换（n 系 → E 系）

`att_caln2e` 算法流程（伪代码，仅指导）：

```
function att_caln2e(nav_info) -> NavInfo:

  blh = WGS84XYZ2BLH(nav_info.pos)                  # ECEF → LLH
  nav_info.rotation = CalCn2e(blh.lat, blh.lon) @ nav_info.rotation  # n 系姿态 → E 系
  nav_info.quat = RotationMatrix2Quaternion(nav_info.rotation)
  return nav_info
```

**转换逻辑**：

```
输入：n 系下的姿态 C_b^n（由对准过程计算）
输出：E 系下的姿态 C_b^e

步骤：
  1. 由 ECEF 位置计算 LLH：[lat, lon, h] = WGS84XYZ2BLH(pos_e)
  2. 构造 n→e 旋转矩阵：C_n^e = CalCn2e(lat, lon)
  3. 转换姿态：C_b^e = C_n^e @ C_b^n
  4. 转换四元数：q_b^e = dcm2quat(C_b^e)

速度转换：
  vel_e = C_b^n^T @ vel_ned  或  vel_e = C_n^e^T @ vel_ned
  （具体取决于速度定义在哪个系）
```

### 11.4 装配伪代码

```
function assemble_state(gnss, att_rpy, imu_error_config, config) -> InsState:

  # 1. 位置/速度（ECEF）
  pos_e = gnss.pos
  vel_e = gnss.vel
  timestamp = gnss.timestamp

  # 2. 姿态转换 n 系 → E 系（参考 AttCaln2e）
  pos_llh = ecef2llh(pos_e)
  C_b_n = euler2dcm(att_rpy)              # [roll, pitch, yaw] → C_b^n
  C_n_e = CalCe2n(pos_llh.lat, pos_llh.lon).T   # 注意 CalCn2e 返回的是 C_n→e
  C_b_e = C_n_e @ C_b_n
  q_b_e = dcm2quat(C_b_e)

  # 3. IMU 误差
  #    初始化调整.md：一般只初始化加速度计和陀螺零偏
  #    单位转换常量:
  #      dh2rs = π/180/3600, constant_mGal = 1e-6×g0, constant_ppm = 1e-6
  #    零偏优先使用静态标定结果 (_calibrate_bias_from_static_imu),
  #    否则从 config 读取
  if static_mode and calibrated_gyro_bias is not None:
    gyro_bias  = calibrated_gyro_bias      # 静态标定结果 (rad/s)
    accel_bias = calibrated_accel_bias     # 静态标定结果 (m/s²)
  else:
    gyro_bias  = config.initial_gyro_bias  * dh2rs            # °/hr → rad/s
    accel_bias = config.initial_acce_bias  * constant_mGal    # mGal → m/s² (1e-6×g0)
  # 已放弃: gyro_scale  = config.initial_gyro_scale * constant_ppm      # ppm → 无量纲
  # 已放弃: accel_scale = config.initial_acce_scale * constant_ppm      # ppm → 无量纲
  # 注意：本项目当前 config 值置 0, 依赖 EKF 在线估计; 接口已就位供后续填入标定值

  # 4. 安装角与杆臂
  imu_angle = config.initial_imu_angle * deg2rad             # [pitch, yaw] (rad)
  imu_leverarm = config.initial_imu_leverarm                 # [lx, ly, lz] (m, b 系)
  leverarm = config.leverarm                                 # GNSS 天线杆臂 (m, b 系)

  # 5. 装配 InsState
  state = InsState(
    timestamp    = timestamp,
    pos_e        = pos_e,
    vel_e        = vel_e,
    C_b_e        = C_b_e,
    q_b_e        = q_b_e,
    att_rpy      = att_rpy,
    gyro_bias    = gyro_bias,
    accel_bias   = accel_bias,
    # 已放弃: gyro_scale   = gyro_scale,
    # 已放弃: accel_scale  = accel_scale,
    imu_angle    = imu_angle,
    imu_leverarm = imu_leverarm,
    leverarm     = leverarm,
  )

  return state
```

### 11.5 注意事项

- **prevapre 与 pvacur 相同**：参考 KF-GINS `initialize` 行 78，初始化时 `pvapre_ = pvacur_`，即上一时刻状态与当前状态相同，第一次机械编排时 `dt` 由下一个 IMU 历元决定
- **IMU 误差初始值**：若 IMU 已做过标定，使用标定值；否则置零，由 EKF 慢慢收敛
- **安装角与杆臂**：初始化时使用配置值，后续由 EKF 在线估计（StateIndex 可选参数块）
- **坐标系一致性**：所有状态量最终表示在 E 系下，对准过程中产生的 n 系中间量（如 `vel_ned`、`C_b_n`）需立即转回 E 系

## 12. 初始协方差矩阵设置

### 12.1 单滤波协方差统一装配

### 12.3 不同对准模式下的姿态协方差默认值

不同对准模式下的姿态协方差默认值如下：

```
if use_define_variance_att or aligned_mode == SETTING:
  # 使用配置值
  att_std = config.initial_att_std * deg2rad   # 度 → 弧度

  # 按对准模式默认
```

单滤波架构下，IMU 安装角/杆臂与 GNSS 杆臂等已合并到 P 的可选参数块，由 `StateIndex` 索引管理（未启用时索引为 -1）：

**默认值**：

- GNSS 杆臂 std：0.5 m（三轴）
- IMU 安装角 std：5°（pitch, yaw）

### 12.5 装配伪代码

```
function set_initial_variance(state, gnss, aligned_mode, config, si) -> P:
  # si 为 StateIndex（参考 estimator.md 第 2.1 节），si.dim = 15~24

  # ===== 固定 15 维 =====
  P = zeros((si.dim, si.dim))

  # 位置/速度协方差
  if config.use_define_variance_pos_vel:
    P[0:3, 0:3] = diag(config.initial_pos_std ** 2)
    P[3:6, 3:6] = diag(config.initial_vel_std ** 2)
  else:
    P[0:3, 0:3] = gnss.cov[0:3, 0:3]
    P[3:6, 3:6] = gnss.cov[3:6, 3:6]

  # 姿态协方差
  if config.use_define_variance_att or aligned_mode == SETTING:
    att_std_rad = config.initial_att_std * deg2rad
    P[6:9, 6:9] = diag(att_std_rad ** 2)
  else:
    if aligned_mode == IN_MOTION:
      att_std_rad = [5.0 * deg2rad, 5.0 * deg2rad, 5.0 * deg2rad]
    elif aligned_mode == STATIONARY_AND_MOTION:
      att_std_rad = [2.0 * deg2rad, 2.0 * deg2rad, 5.0 * deg2rad]
    P[6:9, 6:9] = diag(att_std_rad ** 2)

  # 陀螺零偏协方差
  gyro_bias_std = config.gyro_bias_std * (D2R / 3600.0)   # °/hr → rad/s
  P[9:12, 9:12] = diag(gyro_bias_std ** 2)

  # 加计零偏协方差
  accel_bias_std = config.acce_bias_std * constant_mGal   # mGal → m/s² (1e-6×g0)
  P[12:15, 12:15] = diag(accel_bias_std ** 2)

  # ===== 可选参数块（StateIndex 索引管理，未启用时索引为 -1）=====
  if si.has_lever_arm():
    leverarm_std = config.leverarm_std
    P[si.lever_arm : si.lever_arm+3, si.lever_arm : si.lever_arm+3] = diag(leverarm_std ** 2)
  if si.has_imu_angle():
    imu_angle_std = config.imu_angle_std * deg2rad        # 度 → 弧度
    P[si.imu_angle : si.imu_angle+2, si.imu_angle : si.imu_angle+2] = diag(imu_angle_std ** 2)
  if si.has_imu_leverarm():
    imu_leverarm_std = config.imu_leverarm_std
    P[si.imu_leverarm : si.imu_leverarm+3, si.imu_leverarm : si.imu_leverarm+3] = diag(imu_leverarm_std ** 2)

  # 对称性保证
  P = 0.5 * (P + P^T)
  return P
```

### 12.6 注意事项

- **协方差为标准差平方**：装配时记得对标准差平方（参考 KF-GINS `initialize` 行 83-89，使用 `cwiseProduct` 即元素乘）
- **单位一致性**：姿态协方差的单位是 rad²，位置协方差是 m²，速度协方差是 (m/s)²，零偏协方差需转换到标准单位
- **对称性保证**：装配后 `P = 0.5 * (P + P^T)`
- **正定性保证**：所有对角元素必须为正，最小特征值 ≥ 1e-12
- **KF-GINS 的协方差装配**：参考 `gi_engine.cpp:80-89`，KF-GINS 直接使用配置的 `initstate_std` 平方作为对角线，不区分对准模式；本项目采用按对准模式区分的更细粒度策略

### 13.3 第一次机械编排的特殊处理

参考 KF-GINS `addImuData` 的 `compensate=true` 参数（行 53-55）：

```cpp
    imupre_ = imucur_;
    imucur_ = imu;
```

**第一次机械编排的特殊处理**：
- 初始化完成后，第一个 IMU 历元（即对齐到 `t_gnss` 的 IMU）作为 `imupre`
- 第一个 IMU 历元需要**补偿 IMU 误差**（陀螺零偏、加计零偏），参考 `imuCompensate`
- 后续 IMU 历元作为 `imucur`，与 `imupre` 配对进行机械编排
- 第一个机械编排的 `dt` 由 `imucur.timestamp - imupre.timestamp` 计算

### 13.5 注意事项

- **初始化可重复触发**：系统启动后首次匹配到 GNSS 时执行初始化；长时间 GNSS 中断后识别 reboot，需要重新进入初始化流程（详见第 13.6 节）
- **imupre 与 imucur 配对**：第一次机械编排需要 `imupre` 与 `imucur` 都有效；初始化完成时设置 `imupre`，下一个 IMU 历元作为 `imucur`
- **GNSS 速度方向作为航向**：动对准模式下，`yaw` 来自 GNSS 速度方向，因此初始化时刻车辆必须有运动（速度超阈值）
- **状态切换**：`UNINITIALIZED → INITIALIZED` 不是单向的；GNSS 中断超阈值或 IMU 数据中断时回退到 `UNINITIALIZED`，等待重新初始化（参考 KF-GINS `addImuData(imu_cur, true)` 的 `true` 参数）
- **协方差反馈**：初始化后第一次 EKF 量测更新会显著降低位置/速度协方差（来自 GNSS），姿态协方差需要较长时间收敛

### 13.6 Reboot 识别与重新初始化

> **用户原话**：注意初始化模式需要识别 reboot，当第一次初始化后，长时间没有 GNSS 观测还要继续进行初始化，与数据对齐统一调度识别 reboot。

#### 13.6.1 设计目标

系统首次初始化成功后进入机械编排主循环。若运行过程中出现以下情况，需要识别为 "reboot"（重启）事件，**回退到 `UNINITIALIZED` 状态，重新进入初始化流程**：

1. **长时间无 GNSS 观测**：GNSS 中断时长超过 `gnss_outage_threshold`（如 30 秒），INS 长时间纯惯导推算导致位置/速度发散，可信度丧失
2. **IMU 数据中断**：IMU 数据流中断，机械编排无法继续
3. **协方差发散**：协方差 `P` 对角元素超过 `cov_divergence_threshold`，状态估计已不可信
4. **GNSS 解算模式降级**：从 RTK Fixed 长时间降级到 SPP（可选，根据应用场景配置）

**与数据对齐统一调度识别 reboot**：reboot 识别由 `Aligner`（数据对齐模块）与 `InsInitializer`（初始化模块）**协同完成**：

- `Aligner` 负责检测数据流层面的 reboot 信号（GNSS 中断、IMU 中断、时间戳跳变）
- `InsInitializer` 负责检测状态层面的 reboot 信号（协方差发散、解算模式降级）
- 两者通过共享 `RebootEvent` 事件统一调度

#### 13.6.2 Reboot 触发条件

| 触发条件 | 阈值配置 | 默认值 | 检测方 | 处理 |
|---------|---------|--------|-------|------|
| GNSS 中断超时 | `gnss_outage_threshold` | 30 s | `Aligner` | 标记 GNSS reboot |
| IMU 中断超时 | `imu_outage_threshold` | 1 s | `Aligner` | 标记 IMU reboot |
| 时间戳跳变 | `timestamp_jump_threshold` | 10 s | `Aligner` | 标记时间 reboot |
| 协方差发散 | `cov_divergence_threshold` | 100 m² | `InsInitializer` / `LcIntegration` | 标记状态 reboot |
| GNSS 模式降级 | `gnss_mode_degrade_threshold` | 60 s | `LcIntegration` | 标记模式 reboot（可选） |

#### 13.6.3 与 Aligner 的协同机制

参考 [imu.md 数据流时序](file:///home/mxl/workplace/gipylib/skills/imu.md) 和 [logANDoutput.md Logger 设计](file:///home/mxl/workplace/gipylib/skills/logANDoutput.md)，`Aligner` 是数据对齐的核心调度器，负责维护 IMU/GNSS 时间对齐。reboot 识别应与 `Aligner` 的调度统一：

```
┌─────────────────────────────────────────────────────────────────┐
│ Aligner (数据对齐调度器)                                         │
│                                                                 │
│  harvest() 循环:                                                │
│    1. 从 imu_queue 收割 IMU 数据                                │
│    2. 从 gnss_queue 收割 GNSS 数据                              │
│    3. 检测 reboot 信号:                                         │
│       ├── GNSS 中断超时 → 触发 RebootEvent(GNSS_OUTAGE)         │
│       ├── IMU 中断超时 → 触发 RebootEvent(IMU_OUTAGE)           │
│       └── 时间戳跳变 → 触发 RebootEvent(TIMESTAMP_JUMP)         │
│    4. 输出 AlignedBlock 或 RebootEvent 到 estimate_queue        │
└─────────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────────┐
│ LcIntegration (主循环消费者)                                     │
│                                                                 │
│  process_epoch(item):                                           │
│    if item is RebootEvent:                                      │
│      handle_reboot(item)  # 第 13.6.4 节                        │
│    elif item is AlignedBlock:                                   │
│      if state == UNINITIALIZED:                                 │
│        InsInitializer.initialize(item, config)  # 重新初始化    │
│      else:                                                      │
│        normal_mechanization(item)                               │
└─────────────────────────────────────────────────────────────────┘
```

#### 13.6.5 配置项

| 配置项 | 类型 | 默认值 | 含义 |
|--------|------|--------|------|
| `gnss_outage_threshold` | double | 30.0 | GNSS 中断超时阈值（秒），超过则触发 reboot |
| `imu_outage_threshold` | double | 1.0 | IMU 中断超时阈值（秒），超过则触发 reboot |
| `timestamp_jump_threshold` | double | 10.0 | 时间戳跳变阈值（秒），超过则触发 reboot |
| `cov_divergence_threshold` | double | 100.0 | 协方差发散阈值（m²），协方差 P 对角元素最大值超过则触发 reboot |
| `enable_gnss_mode_degrade_reboot` | bool | false | 是否启用 GNSS 模式降级 reboot（如 RTK→SPP） |
| `gnss_mode_degrade_threshold` | double | 60.0 | GNSS 模式降级持续时间阈值（秒） |
| `reboot_use_prior_state` | bool | false | reboot 后重新初始化时是否使用前一次状态作为先验 |

#### 13.6.6 注意事项

- **GNSS 中断阈值选择**：30 秒默认值适用于车辆场景；航空场景可放宽到 60 秒（GNSS 短暂遮挡常见）；行人场景应收紧到 10 秒
- **IMU 中断阈值**：1 秒默认值是因为 IMU 通常 100 Hz，中断 1 秒意味着 100 个历元缺失，机械编排无法外推
- **协方差发散阈值**：100 m² 对应位置标准差 10 m，已超出 GNSS SPP 精度，无意义继续推算
- **reboot 后的先验使用**：默认不使用前一次状态作为先验（`reboot_use_prior_state = false`），完全重新初始化；若协方差仍在可信范围内，可启用先验模式加速收敛
- **与 Aligner 的接口**：`Aligner` 输出的 `RebootEvent` 应包含足够信息（事件类型、时间戳、中断时长），便于 `LcIntegration` 决策
- **多次 reboot**：连续多次 reboot 应触发告警，可能是硬件故障或配置问题
- **数据对齐统一调度**：reboot 识别不应在 `InsInitializer` 内部独立完成，而应通过 `Aligner` 统一调度，避免多个模块各自检测导致状态不一致
