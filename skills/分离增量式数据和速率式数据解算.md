# 分离增量式数据和速率式数据解算 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 在不改变现有速率式 IMU 解算结果的前提下，为松组合增加原生 ECEF 增量式机械编排路径；`a-kfgins-data/Leador-A15.txt` 不再转换为速率，GNSS 跨 IMU 区间时按 KF-GINS 方法切分当前增量。

**架构：** `ImuMeasurement` 继续承载公共时间信息，但内部 payload 明确区分 `RateImuData` 与 `IncrementImuData`。速率数据沿用 GVINS 风格线性速率插值；增量数据保存原始 `dtheta/dvel/dt/sow`，采用 KF-GINS 的 1 ms 时间判定和当前增量比例切分。ECEF 机械编排在入口处分别取得原始增量，之后统一复用现有零偏、比例因子、圆锥/划桨、地球自转、重力和位置更新。

**技术栈：** Python 3.12、NumPy、pytest、现有 GInsStream LC/ECEF 机械编排、仓库内 `tools/kf-gins` 参考实现、`a-kfgins-data` 数据集。

## 1. 当前问题与基线

当前 `AwesomeImuFormator` 将每行

```text
sow dtheta_x dtheta_y dtheta_z dvel_x dvel_y dvel_z
```

强制转换为：

```python
gyro = dtheta / unix_timestamp_dt
accel = dvel / unix_timestamp_dt
```

完整 IMU 区间内可以满足 `rate * pipeline_dt == raw increment`，但 GNSS 位于两个 IMU 时刻之间时，`LcIntegration` 使用 `imu_interpolate_linear()` 插值前后两条速率：

```text
project increment = interpolated_rate * dt1 + current_rate * dt2
KF-GINS increment = current_raw_increment
```

这两式仅在相邻速率相同或 GNSS 与区间端点重合时相等。对 `458700--458800` 的 101 个 GNSS 边界，当前路径相对 KF-GINS 当前增量切分产生：

| 项目 | RMS 范数 | 最大范数 |
|---|---:|---:|
| `dtheta` 边界误差 | `4.59699e-6 rad` | `1.52064e-5 rad` |
| `dvel` 边界误差 | `1.84990e-4 m/s` | `7.06122e-4 m/s` |

```text

a-kfgins-data/kf-output
a-kfgins-data/rtklc-outage-output
a-kfgins-data/kf-outage-output
```

## 2. 方案比较与最终选择

### 方案 A：继续统一转换为速率

- 优点：改动最少。
- 缺点：无法在 GNSS 边界保持原始增量守恒；不能等价复现 KF-GINS。
- 结论：不采用。

### 方案 B：同一 `gyro/accel` 字段增加 `data_type` 标志

- 优点：调用点改动较少。
- 缺点：字段单位随标志变化，遗漏一次分支就会把 `rad` 当作 `rad/s` 或把 `m/s` 当作 `m/s²`；不满足“显式分离”的目标。
- 结论：不采用。

### 方案 C：公共外壳 + 两种强类型 payload

- 优点：类型和单位明确；时间对齐与机械编排可按 payload 分派；速率路径可保持原行为；测试容易覆盖增量守恒。
- 缺点：需要迁移直接访问 `imu.gyro/imu.accel` 的初始化、约束、静态检测和日志代码。
- 结论：采用。

## 3. 数据模型与数学约定

计划在 `src/core/data_types.py` 中定义：

```python
@dataclass
class RateImuData:
    gyro: np.ndarray       # rad/s
    accel: np.ndarray      # m/s^2


@dataclass
class IncrementImuData:
    dtheta: np.ndarray     # rad，当前采样区间累计角增量
    dvel: np.ndarray       # m/s，当前采样区间累计速度增量
    dt: float              # s，来源文件中相邻 SOW 的精确差
    sow: float             # s，当前样本原始 GPS 周内秒


@dataclass
class ImuMeasurement:
    timestamp: float
    week: int
    payload: RateImuData | IncrementImuData


# 在现有 GnssSolution 中增加；Awesome 解析器直接保存输入行的 SOW。
GnssSolution.source_sow: float | None = None
```

统一提供以下只读访问器，调用方不直接猜测单位：

```python
def is_rate(imu: ImuMeasurement) -> bool
def is_increment(imu: ImuMeasurement) -> bool
def rate_view(imu: ImuMeasurement, fallback_dt: float | None = None) -> RateImuData
def increment_view(imu: ImuMeasurement, propagation_dt: float) -> IncrementImuData
```

约束：

1. `RateImuData` 没有 `dtheta/dvel` 字段。
2. `IncrementImuData` 没有 `gyro/accel` 字段。
3. 增量 `dt` 必须有限且大于 `1e-6 s`。
4. 增量的机械编排时间使用 payload 的精确 `dt`，不再使用两个大 Unix 浮点数相减。
5. `timestamp` 继续用于跨传感器排序和现有输出时间，不改变 GNSS/RTKLIB 时间系统。
6. 增量拆分必须先拆原始 `dtheta/dvel`，再分别进行零偏和比例因子补偿。
7. Awesome 增量路径只使用 `IncrementImuData.sow` 与 `GnssSolution.source_sow` 计算边界差和 lambda；二者缺失时明确报错，不回退到 Unix 浮点差。

## 4. KF-GINS 增量时间对齐规则

仅对 `IncrementImuData` 使用以下规则，对齐 `GIEngine::isToUpdate()` 与 `GIEngine::imuInterpolate()`：

```text
abs(t_previous - t_gnss) < 0.001 s:
    在 previous 状态执行 GNSS 更新
    随后完整传播 current 增量

abs(t_current - t_gnss) <= 0.001 s:
    完整传播 current 增量
    在 current 状态执行 GNSS 更新

t_previous < t_gnss < t_current:
    lambda = (sow_gnss - sow_previous) / (sow_current - sow_previous)
    head.dtheta = current.dtheta * lambda
    head.dvel   = current.dvel   * lambda
    head.dt     = current.dt     * lambda
    head.sow    = sow_gnss
    tail.dtheta = current.dtheta - head.dtheta
    tail.dvel   = current.dvel   - head.dvel
    tail.dt     = current.dt     - head.dt
    tail.sow    = current.sow
    propagate(head)
    gnss_update()
    propagate(tail)
```

必须满足：

```python
head.dtheta + tail.dtheta == current.dtheta
head.dvel + tail.dvel == current.dvel
head.dt + tail.dt == current.dt
```

切分误差容限：向量逐分量绝对误差不超过 `1e-15`，时间误差不超过 `1e-12 s`。

圆锥/划桨历史与 KF-GINS 一致：第一段使用“上一完整增量 + head”，GNSS 反馈后第二段使用“已补偿 head + 新状态补偿后的 tail”。禁止用上一条速率与当前速率插值得到 head。

## 5. ECEF 原生增量机械编排

`InsUpdate.update()` 入口分派后，统一进入现有 ECEF 算法：

```python
if isinstance(imu.payload, RateImuData):
    dt = imu.timestamp - previous_timestamp
    raw_dtheta = imu.payload.gyro * dt
    raw_dvel = imu.payload.accel * dt
else:
    dt = imu.payload.dt
    raw_dtheta = imu.payload.dtheta.copy()
    raw_dvel = imu.payload.dvel.copy()

dtheta_comp = (raw_dtheta - gyro_bias * dt) / (1.0 + gyro_scale)
dvel_comp = (raw_dvel - accel_bias * dt) / (1.0 + accel_scale)
w_b_ib = dtheta_comp / dt
f_b = dvel_comp / dt
```

后续保持不变：

- `C_b_e_new = R_e(-omega_ie*dt) @ C_b_e @ R_b(dtheta_comp + coning)`；
- 旋转补偿和划桨补偿直接使用已补偿增量；
- 重力和科氏项乘精确 `dt`；
- 位置使用梯形积分；
- `F/Phi/Q` 使用该段对应的 `dt`、`f_b`、`w_b_ib`；
- 闭环反馈仍在 GNSS 更新后生效，tail 使用反馈后的 bias/scale。

本阶段不改变 ECEF 误差模型、不转换 KF-GINS 的完整 N 系模型、不调整 GNSS 标准差和 IMU 噪声参数。
