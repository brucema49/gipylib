更新时间：2026-09-15（Asia/Shanghai，`dev-ubuntu`）

> **结论先行（本轮已收敛）**：机械编排在测量更新点之间的发散不是 DD/观测行集合问题，而是

## ⚠️ 后续开发必读：本轮暴露的问题与教训（强警示）

> **这一节是红线提示，不是背景材料。**
> “机械编排发散”被错误追查了很久：先后怀疑过 DD 行集合、参考星切换、初始化航向差
> （`14.53°`）、phase-code/ambiguity 时域语义、`P/H/R` 坐标契约、反馈时序……
> **真正的根因只有两个零偏参数**。下面每条都是用大量试错换来的，动手前请先读完。

### 🔴 P1：零偏初值单位陷阱 —— `acce_bias_std_si` 曾被当成 mg 填，小了 102 倍

| | 值 | 来源 |
|---|---|---|
| 原配置 | `4.89016338575e-4` | 被当作 “0.05 mg” 换算成 SI |
| **GREAT 实际进入 P 的值** | **`0.05` (m/s²) = 5.11 mg** | `gsetins.cpp:646` + `gins.cpp:552` |

**为什么容易错**：GREAT 写的是 `Vector3d(5e-2,...)/t_gglv::mg`，回填时又
`db_tmp * t_gglv::mg`，除完再乘回，**进入 P 的就是字面量 `0.05`（m/s²）**。
配置项名里的 `_si` 表示“SI 单位”，历史上却按“mg 数值”填了进去。

> **规则**：凡是 `*_std_si` / `*_psd` 结尾的配置，写入前必须回到 GREAT 源码确认
> “进入 `Pk`/`Qt` 那一刻的数值与单位”，而不是看 XML 注释或 `Description` 属性。

### 🔴 P2：零偏过程模型与 GREAT 不一致 —— 一阶马尔可夫 τ=36 s vs 随机游走

GREAT `gins.cpp:32,46` 把 `_tauG/_tauA` 恒置零向量，`416-418` 直接把它写成
`eb-eb`/`db-db` 对角块 ⇒ **零偏是纯随机游走，没有 `-I/τ` 阻尼**。
gipylib 缺省用 `τ = 0.01 h = 36 s`，使 `P_bg/P_ba` 收敛到 `Q·τ/2` 的稳态
（`0.36 deg/h` / `0.133 mg`）后**不再增长**，等价于给零偏加了一个“回到零”的约束。

> **规则**：`τ` 越小，滤波器越“确信”零偏不变，越拒绝修正它。把零偏当常数会
> 直接把未补偿零偏转成**横轨速度误差 → 每秒 0.5 m 级漂移 → 整秒更新点 3.5 m 跳变**。
> 与 GREAT 对照时必须显式声明 `gyro_bias_corr_time_s: .inf /
> acce_bias_corr_time_s: .inf`；其它配置保留 36 s 缺省。

### 🔴 P3：滤波器“过度自信”时，精度指标依然好看 —— 必须看一致性统计量

修正前窗口 ENU RMS `2.0 m` 级别，单看 RMS 只会觉得“精度差”，看不出根因。真正报警的是：

| 一致性指标 | 修正前 | 修正后 | 说明 |
|---|---|---|---|
| 归一化新息中位数 | **`6.93`** | `4.93` | 应 ≈1~3；远大于 3 说明 `P+R` 严重低估真实误差 |
| 更新点速度反馈量级 | `0.03–0.05 m/s` | — | 而真实速度误差 `0.5 m/s` ⇒ 增益≈0，**速度根本没被修正** |
| 秒内误差是否单调增长 | 是（`+0.12 m/s`） | 否（略收敛） | 这是“机械编排发散”的直接定义 |
| 1 s 位移误差 3D RMS | `0.4311 m` | `0.0414 m` | 与 GREAT `0.0168 m` 同量级 |
| 零偏状态是否被冻结 | **是**（窗口内 `178.96~180.40` 几乎不动） | 否 | 冻结即“滤波器放弃估计它” |

> **规则**：**不要只用 RMS 判断滤波器健康度**。每次正式重跑都要同时打印
> 归一化新息、更新点位置/速度跳变的中位数与最大值、秒内误差是否单调增长、
> 零偏状态在窗口内的极差。RMS 变差 10% 可以接受，一致性指标恶化必须立刻停。

### 🟠 P5：`vel_psd` 历史实验的教训 —— 不要靠“放大噪声”压跳变

2026-09-14 19:02 曾把 `vel_psd` 换成 GREAT CPT 模型的 `4.687225e-7`，结果频繁触发 TC
recovery，窗口 RMS 膨胀到 `572/376/684 m`。**放大过程噪声会掩盖真实误差来源**，
本轮证明真正的修法是让零偏“可估计”，而不是让 `P` 变大。

> **规则**：出现跳变先查**状态可估计性**（初值方差、过程模型、可观测量），
> 最后才考虑 `Q`。任何 `Q`/`R`/权重/门限修改都必须先给出源码或数学闭合证据。

### 🟠 P6：误判路径清单 —— 不要再重复踩

以下方向本轮**已查证不是根因**（不要再投入）：

2. 初始化航向差 `14.53°`（gipylib `-130.78°` vs GREAT `-145.31°`）—— 是**结果**不是原因：

4. `pos_psd/vel_psd/gyro_psd/accel_psd/gyro_bias_psd/acce_bias_psd` —— 经 `Qt` 展开复核
   **与 GREAT 完全一致**（见“本轮修正”），不是问题。
5. 机械编排公式（锥补/划桨/旋转补偿/重力/哥氏）—— 与 PSINS/GREAT 同构，二阶差异远小于观测到的量级。

## GREAT 的真实处理顺序（源码核对）

已核对 `/home/mxl/workplace/GREAT-MSF-stage-trace/src/LibGREAT/gmsf/gintegration.cpp`、`gproc/gpvtflt.cpp`、`gins/gins.cpp`：

1. `_GNSS_Update()` 先把 INS 精确传播到 GNSS 端点，再调用 `_processEpoch()`；更新和反馈发生在同一个端点。
2. `_processEpoch()` 每次循环首先删除上一轮后验检验指出的整颗卫星；然后用当前 INS 天线位置调用 `_external_pos()`，把 rover 坐标先验设为当前 INS 名义坐标，坐标 RMS 取当前 `P` 的位置对角线。
3. `_prepareData()`/`_cmp_equ()` 保留同历元可用观测，生成完整方程；没有先用 RTKLIB `maxinno` 把大几何残差行删除。
4. `_combineDD()` 以单差协方差构造双差协方差 `P_DD=(D R_single^{-1}D^T)^{-1}`；滤波器直接消费该 `P_DD`，其逆才是双差权阵。`_merge_pose()` 将坐标列变号，并按杆臂旋转耦合姿态列。
5. 先做滤波更新，再计算 `v_orig=l-A*dx` 和 `Qv=A P_after A^T+R` 的归一化后验残差。超过 XML `max_res_norm=3` 时删除最大残差所属卫星、重新选参考星、重新构造 DD/R，并在同一历元重试；直到通过或观测数不足。
6. 通过后立即执行完整反馈：`pos/vel/att` 减误差，陀螺/加计零偏加误差，随后清零误差状态。源码没有“把位置修正摊到未来 IMU 点”的机制。

这解释了 GREAT 轨迹平滑的来源：不是后处理画图，也不是反馈时间分配，而是每个 GNSS 端点都使用同一先验、完整 DD 系统和同历元卫星级重建，避免欠约束矩阵把误差集中到少数位置/速度状态。

## 已完成的 gipylib 结构修正

### 1. 禁止时间分配反馈

`src/core/tc/tc_estimator.py` 已删除 pending position correction 及按时间分摊逻辑。`feedback()` 在 GNSS 更新端点直接调用通用闭环反馈；配置中不存在可重新打开该方法的开关。

### 2. 量测前/后粗差顺序对齐

`src/core/tc/tc_measurement.py` 新增显式 `gnss.prefit_outlier_enable`。正式 GREAT 配置在 `data-great/rtktc-rate.yaml` 和 `data-great/rtktc-increment.yaml` 中设为 `false`：完整同历元 DD 候选集先进入 EKF，保留原 `maxinno/maxcode` 数值供 legacy 配置使用；正式路径不改变这些阈值，只不在滤波前使用它们。

### 3. 真正的同历元卫星级 DD 重建

此前尝试过对冻结的 `H/R` 行切片；该实验会保留旧参考星和旧协方差，已证明不是 GREAT 的算法，正式配置关闭。当前实现由 `RtkTcMeas.build()` 保存同历元几何/观测数组，`TcEstimator.tc_meas_update()` 在后验失败后：

- 恢复更新前完整 `x/P`；
- 删除最大归一化残差所属目标卫星（参考星也作为候选）；
- 重新进入 `_build_dd()`，重新选择参考星并重新计算 DD 协方差；
- 在相同 GNSS 端点反复检查后验残差；
- 将最终重建后的 `v/H/R/pairs` 写入矩阵诊断，避免用重建前的行号配对后验量。

这条路径不重复 `udbias`，不改变噪声、权重或门限，只修复 GREAT 事件顺序和 DD 身份一致性。

### 初始不确定度（GREAT ADIS16470 映射）

> ⚠️ **本小节就是“机械编排发散”两个根因之一的所在地**，详见 P1 / P4。
> 改这里的任何数字前，必须先给出 GREAT 源码行号。

- 位置 `[3,3,3]` m；速度 `[0.5,0.5,0.5]` m/s；姿态 `[0.5,0.5,5]` deg。
- 陀螺零偏 120 deg/h。
- **加计零偏 `0.05 m/s²`（= 5.11 mg）。此前写成 `0.05 mg`，比 GREAT 小 102 倍，是本轮主要根因之一，已修正。**
- 初始化配置的 yaw 标准差保持显式值，不被旧默认值覆盖。

GREAT 源码依据（`GREAT-MSF-stage-trace/src/LibGREAT`）：

```cpp
// gset/gsetins.cpp:642-650  (IMU_TYPE::ADIS16470 模型表)
GyroBiasInitialSTD = Vector3d(120, 120, 120);                       // deg/h
AcceBiasInitialSTD = Vector3d(5e-2, 5e-2, 5e-2) / t_gglv::mg;       // = 5.1121 (mg)

// gins/gins.cpp:551-553  回填 P
v << angle_tmp * deg, v_tmp, pos_tmp, eb_tmp * dph, db_tmp * mg;
v = v.array().abs2();
Pk = v.array().matrix().asDiagonal();
```

`AcceBiasInitialSTD` 先除以 `t_gglv::mg`（`= 1e-3*g0 = 9.7803267714e-3`），回填时又乘回
`mg`，因此**进入 P 的数值就是 `0.05`（m/s²）**，即 `5.11 mg`。gipylib 的 `P` 以 SI
（`m/s²`）为单位，所以配置项 `acce_bias_std_si` 必须直接写 `0.05`，而不是 `0.05 mg`
（`4.89016338575e-4 m/s²`）。注意 `<Estimator>` 里 XML 的
`AcceBias InitialSTD="10,10,10"` 并不生效：`gsetign.cpp:409` 在
`_imu_type != Customize` 时直接返回模型表值，本配置的 `IMUErrorModel Type="ADIS 16470"`
不是 `Customize`。

### 零偏过程模型（GREAT 是随机游走，不是一阶马尔可夫）

> ⚠️ **本小节是“机械编排发散”的另一个根因**，详见 P2。
> `τ` 越小 ⇒ 滤波器越确信零偏不变 ⇒ 越拒绝修正它 ⇒ 未补偿零偏直接变成横轨漂移。

```cpp
// gins/gins.cpp:32,46   —— 全文只有这两处赋值, 均为零向量
eb = db = _tauG = _tauA = _tauGScale = _tauAScale = Vector3d::Zero();

// gins/gins.cpp:416-418
Ft.block(9,  9,  3, 3) = sins._tauG.array().matrix().asDiagonal();   // eb-eb  = 0
Ft.block(12, 12, 3, 3) = sins._tauA.array().matrix().asDiagonal();   // db-db  = 0
```

GREAT 的零偏**没有 `-I/τ` 阻尼**，是纯随机游走。gipylib 的
`TransferMatrix` 缺省用 `τ = 0.01 h = 36 s` 的一阶马尔可夫，使 `P_bg/P_ba` 收敛到
`Q·τ/2` 的稳态（`0.36 deg/h` / `0.133 mg`）后不再增长，等价于给零偏加了一个“回到零”的
约束，滤波器因此拒绝继续修正零偏。

修正方式：`gyro_bias_corr_time_s` / `acce_bias_corr_time_s` 现在接受 `+inf`，
`_gm_block()` 在 `τ=+inf` 时返回零块（随机游走）。缺省仍是 36 s，其它配置行为不变；
只有两份 GREAT 对照 YAML 显式声明 `.inf`。

### 过程噪声 P/Q 入口

> ⚠️ **2026-09-15 配置三段化后**：`pos_psd` / `vel_psd` 已被登记为**松组合专属**
> （`config_loader.INS_LC_ONLY_KEYS`），从两份 TC 正式配置中移除。下表 `pos_psd=1.0e-08`
> 是三段化之前的取值；当前 TC 配置**不写这两个键**。移除 `pos_psd` 后重跑，
> `nav-100hz.csv` 与三段化前差异 RMS `0.000027 m`、最大 `0.000111 m`（数值噪声量级），
> 窗口 ENU RMS 仍为 `0.4500/0.2155/0.2267 m`，即该键对 TC 无实质影响。

当前正式 YAML 使用 GREAT ADIS16470 的物理单位换算：

```text
gyro_psd      = 7.11620139001727e-09  rad²/s
accel_psd     = 4.72278200625e-07    m²/s³
gyro_bias_psd = 1.72231306427737e-13  rad²/s³
acce_bias_psd = 1.0010896e-07         m²/s⁵
（pos_psd / vel_psd：松组合专属，紧组合配置不写，见上）
```

`vel_psd=0` 并不表示速度协方差不传播；速度不确定度来自加速度噪声和 `Phi P Phiᵀ` 耦合。紧组合中没有独立 PVT 速度/位置观测，不能为了“看起来平滑”随意增加 `vel_psd`、`pos_psd` 或运行点 floor。

> ⚠️ **不要靠放大 `vel_psd` 压跳变**（见 P5）：2026-09-14 19:02 把 `vel_psd` 换成
> `4.687225e-7` 后频繁触发 TC recovery，窗口 RMS 膨胀到 `572/376/684 m`。
> 本轮证明正确修法是让零偏**可估计**（初值方差 + 随机游走），而不是让 `P` 变大。

传播实现保留当前与机械编排同一 `dt` 的 `Phi/Q` 快照并使用 Joseph 量测更新；任何后续 P/Q 调整必须先以 GREAT 源码公式和逐历元特征值证据证明，而不能凭精度结果反向调参。

### 量测噪声 R 与 DD 协方差

gipylib 的 `R` 直接存储与 GREAT 更新接口相同的双差观测协方差 `P_DD=(D R_single^{-1}D^T)^{-1}`；每个 DD 块使用参考星单差方差和目标星单差方差，参考星共享项写入块内非对角元素；不同系统/频段块不相互拼接。`matrix_diagnostics_path` 输出每次更新的 R 对角、行索引和排除行，供逐历元与 GREAT `CAMP-MSF.dd-trace.csv` 对照。重建后必须以最终 `pairs` 的行身份读取，不能沿用原矩阵行号。
