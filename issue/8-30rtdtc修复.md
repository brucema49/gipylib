# RTD-TC 平面精度修复规划

## 1. 任务目标

在不把 RTD-TC 的问题误判为 GNSS 输入、姿态初始化或经验参数问题的前提下，定位并修复 `gipylib/data/rtdtc.yaml` 相比纯 RTD `gipylib/data/rtd.yaml` 平面精度明显下降的原因。

本文件是后续执行的唯一入口，当前阶段**只规划，不修改源代码、YAML、评估脚本、原始数据或既有输出**。后续任何实现改动都必须引用本文件的实验编号，并保留可回退的配置和结果快照。

目标数据集：CPT 数据，使用 `data/cpt0870.19o`、`data/cpt0870_base.19o`、`data/brdm0870.19p`、`data/cpt_euroc.csv` 和 `data/truth.csv`。仓库中的 `Data19_20201214_HG4930_CAR_Opensky/` 是另一套 Data19 数据，本 issue 不与其混用。

统一评价窗口：GPS Week `2046`，SOW `359000--359100`；同时报告完整重叠区间和预先登记的最差 100 s 机动窗口。真值为 `data/truth.csv`，ENU 原点、插值方法、整数秒更新点规则必须固定。

## 2. 当前事实与待确认问题

### 2.1 当前实现结构

- `src/core/tc/tc_integration.py` 根据模式选择 `RtdTcMeas` 或 `RtkTcMeas`。
- `src/core/tc/tc_measurement.py` 中二者共同继承 `_DdBase`，共用 `satposs()`、`zdres()`、`selsat()`、双差 LOS Jacobian、粗差筛选和方差计算。
- `RtkTcMeas` 使用载波相位、伪距和模糊度；`RtdTcMeas` 目标是只使用伪距双差、无模糊度。
- 当前工作树的 `RtdTcMeas.build()` 已改为让 `_build_dd()` 在 `use_phase=False` 时直接遍历码频率，并保留 `ddcov` 生成的完整码双差协方差。这是 R1 候选，尚未完成与 RTKLIB code-only 基准、成对回放和精度门槛的验证；不得把它当作已验收结论。
- `tc_estimator.py` 的位置-速度交叉协方差传播和 EKF 更新是 RTK/RTD 公共路径；RTD 没有直接速度量测，只能通过 `P[pos,vel]` 间接修正速度。
- `rtdtc.yaml` 当前启用 `ins.enabled: tc`、GPS-only、`vel_psd: 1.0` 和 DD Doppler 速度量测；`rtd.yaml` 是 GPS-only、INS off。二者的 GNSS 段已对齐，仍须将 INS 状态、Doppler 设置和输出频率作为 TC 变量单独评估。

### 2.2 已有结果只能作为待复现线索

已有 `data/output/rtd.pos` 在目标窗口的纯 RTD 评估约为：水平 RMS `0.265 m`，高程 RMS `0.557 m`，高程均值约 `+0.472 m`。

已有 `data/output/rtdtc-gps-bds.rslt` 是历史输出，文件时间和当前配置不一定一致。该文件头定义的 Qins 位于数据行第 7 列（零基索引 6）；目标窗口实际包含约 101 个 Qins=3 更新点和 10000 个 Qins=2 传播点。此前“没有 Qins=3”的结论来自评估脚本错误使用第 9 列解析 gipylib `.rslt`，不能作为算法结论。

必须先确认：纯 RTD 与 RTD-TC 是否使用同一星座、频点、观测筛选、基站坐标、时间范围和输出版本。若不一致，先修复实验条件，不进入算法归因。

## 3. 成功标准与非目标

### 3.1 成功标准

1. 在同一输入、同一 GPS-only/星座设置、同一频点和同一时间窗口下，RTD-TC 的更新点和全部输出点都能被可靠识别。
2. 纯 RTD 基线不因 RTD-TC 修复而退化。
3. RTD-TC 目标窗口水平 RMSE 达到与纯 RTD 同量级；暂定通过门槛为：相对纯 RTD 增量不超过 `0.03 m`，且不超过纯 RTD 的 `1.15` 倍。若数据条件限制无法达到，必须给出残差、卫星可用性或姿态不可观测性的证据。
4. 全段水平 RMSE、最大水平误差、高程 RMS、有效 GNSS 更新率、首次发散时刻均不得恶化。
5. 不出现新增百米级跳变、量测更新长期中断、非有限/非正定协方差或未解释的降级/重启。

### 3.2 非目标

- 不以单独调大 `vel_psd`、`maxcode`、初始姿态协方差或杆臂参数掩盖量测构造错误。
- 不在没有纯 RTD 对照的情况下宣称 TC 滤波器改善或恶化。
- 不把 RTK-TC 的模糊度固定策略直接移植到没有模糊度的 RTD-TC。

## 4. 实验产物与命名规则

每次实验使用独立目录，例如 `exp-8-30/<ID>/`，并保存：

- 配置副本、代码提交 ID、输入文件 SHA256、运行命令和完整 stdout/stderr；
- 纯 RTD `.pos/.stat`、RTD-TC `.rslt/.stat/trace`；
- 统一评估 JSON/CSV/PNG；
- 逐历元观测审计、量测 `v/H/R`、`S/K/P` 健康诊断；
- `Texp_start/end`、数据 `Tdata_start/end`、`first_bad[Tdata]`、`first_good[Tdata]`、回退版本。

禁止覆盖 `data/output/rtd.pos`、`data/output/rtdtc-gps-bds.rslt` 和任何既有实验目录。

## 5. Phase 0：冻结并复现基线

### P0-1 读取与一致性检查

只读检查以下项目并记录差异：

- rover/base RINEX 头、基站 ECEF、观测开始/结束时间；
- `truth.csv` 的 GPS Week/SOW、IMU Euroc 时间戳和 `utc2gpst` 转换；
- `rtd.yaml` 与 `rtdtc.yaml` 的 `gnss_t`、`nf`、`freq_ix0/1`、`freq_table`、`elmin`、`cnr_min`、`maxcode`、`eratio`、`prnbias`、`vel_psd`、杆臂和 NHC/ZUPT/ZARU；
- `.rslt` 列定义及 Q/Qins 语义。当前输出头声明 `Qins=1/2/3`，评估脚本还支持 `Qins=8/11`，必须以实际 writer 为准。

### P0-2 成对重跑

建立三组候选配置副本，严格区分 GNSS 基线和 TC 影响：

- G0：当前 `rtd.yaml`，保留纯 RTD 基线；
- G1：以 `rtdtc.yaml` 的 GNSS 段为准，设置 `ins.enabled: "off"`，得到与 T0 完全相同的 GNSS 参数；
- T0：与 G1 使用完全相同的 GNSS 段，设置 `ins.enabled: "tc"`，仅增加 IMU/TC 消费。

G1 与 T0 的 GNSS 段必须字节级等价（仅允许 `ins.enabled` 和输出路径/文件名不同）。首轮受控实验固定 GPS-only、`nf=1`、输入文件、基站坐标、频率表、仰角/CNR、粗差门限、输出时间系统和评估窗口；任何未统一字段都要记录，不能直接比较。G0 只保留为历史基线，不作为 T0 的因果对照。按顺序运行：

1. G0 纯 RTD：生成 `.pos`，统计 E/N/U、水平/3D RMS、最大误差、质量和有效历元；
2. G1 同 GNSS 参数的纯 RTD：生成 `.pos`，作为 T0 的无 INS 对照；
3. T0 RTD-TC：生成 `.rslt`，分别统计 `T0-U`（Qins=3 更新点）、`T0-I`（每个整数秒代表点）和 `T0-A`（全部机械编排与更新点）。

若 P0 无法重现已有结果，标记 `RB-P0`，先处理版本/配置/输出口径回归，不得进入参数扫描。

## 6. Phase 1：RTD-TC 输出和更新点语义审计

目标是排除“实际有更新但评估误读为 Qins=2”或“量测更新失败后只输出传播状态”。对于 gipylib `.rslt`，Qins 固定解析为零基第 6 列；ignav 文件按其实际格式单独指定列号，不能复用同一个硬编码列号。

1. 解析 `.rslt` 头和数据列，逐行验证 `Q`、`Qins`、`ns`、速度、姿态、标准差列位置。
2. 从 TC 运行日志/trace 和 `stat` 建立更新事件表：`week,sow,mode,n_meas,n_code_acc,quality,qins,reason`。
3. 对每个事件检查 `last_update_info`、`update_flag`、`_last_q`、降级状态和 fallback；不得用颜色或整数秒近邻推断更新。
4. 修正评估脚本前，先用三条手工历元核对 LLH/ECEF→ENU 误差；评估脚本改动必须单独记录，不能与算法候选混在一起。

通过条件：更新事件、输出 Qins、评估脚本分类三者一致；目标窗口应能识别约 101 个更新点（具体以重跑为准），且 G1/T0 的同历元样本可一一匹配。否则停止后续实验并记录 `ASK-EVAL`。

## 7. Phase 2：量测构造数学对照

### 7.1 共同输入对照

为同一 GNSS 历元保存：rover/base 卫星号、系统、观测码、频率 Hz、伪距/载波有效标志、仰角、SNR、`iu/ir`、参考星、`yr/yu/er/eu`、`dt`。同一历元必须同时送入纯 RTD 与 RTD-TC 诊断入口。

### 7.2 RTD 码双差对照

用 `RtdTcMeas` 与一个只生成 code 的参考实现逐项比较：

- 双差残差 `v`（单位 m）；
- 位置、姿态、杆臂、钟差 Jacobian 的列和值；
- 码量测数量、卫星对及参考星；
- 单差方差、双差协方差的对角和非对角项；
- 粗差拒绝前后数量及拒绝原因。

参考基准必须调用现有 `rtklib.ddres(..., use_phase=False)`；验证脚本不得依赖该函数默认的 `use_phase=True`。比较前固定同一参考星和卫星顺序，并把 RTKLIB 直接位置状态的 H 转换为 TC 误差状态的符号。RTD 不含钟差状态，不要求比较钟差列。若接口不能直接提供 code-only 结果，则在测试夹具中构造等价 code-only DD，而不是修改生产代码。

重点验证当前实现的两个风险：

1. R1 code-only 遍历是否与 RTKLIB `use_phase=False` 的参考星、`nb_per_block`、卫星顺序和 `R` 分块完全一致；
2. R1 是否保留同一参考星引起的码双差相关协方差，并量化其对滤波的影响；
3. RTD 码双差 H 只包含位置（零杆臂时姿态列应为零），不应把缺少速度列误判为构造错误。

通过条件：同一卫星对和同一参考星下，`v/H` 差异在 `1e-6 m` / `1e-8` 量级内，`R` 对称、有限、半正定，且码行数量与参考实现一致。否则建立最小历元夹具并进入 Phase 4。

## 8. Phase 3：RTD-TC 滤波协方差和速度反馈审计

固定通过 Phase 2 的量测输入，不改算法参数，提取每个 RTD 更新点：

- `P[pos,pos]`、`P[vel,vel]`、`P[pos,vel]` 的对角/范数；
- `S=H·P·H^T+R` 的对角、中位数、条件数、最小特征值；
- `K_pos`、`K_vel`、`K_att`、`K_ba`；
- innovation 范数、post-fit、接受/拒绝、fallback、降级；
- 更新前后位置/速度/姿态/零偏修正及更新间传播误差。

需要回答：

1. RTD 的无速度 H 是否仍通过 `P[pos,vel]` 产生合理 `K_vel`；
2. `vel_psd=1.0` 是否把速度协方差人为抬高到失去 INS 记忆，或使码量测过度拉动速度；
3. RTD-TC 首次恶化历元是否与创新接近 `maxcode`、协方差塌缩、参考星切换、姿态发散或 fallback 同时发生；
4. 零杆臂下 `H[att]` 为零是否造成姿态不可观测，并通过重力投影间接造成平面漂移。

判定规则：若量测前后状态健康但姿态在传播中发散，转入姿态可观测性专项；若 `R/S/K/P` 在首次恶化点出现异常，优先修复协方差或量测构造；若所有异常只出现在评估输出，回到 Phase 1。

## 9. Phase 4：单变量修复顺序

只有 Phase 2/3 给出证据后才执行；每轮只改一个变量族，并与 P0 成对比较纯 RTD 和 RTD-TC。

### R1：独立 code-only 构造和完整 R（已实现，待验收）

- 当前候选让 RTD 路径直接遍历码频率，避免生成后再过滤相位；
- 当前候选按码双差 block 调用 `ddcov`，保留同参考星的相关项；
- 验收必须补齐与 `ddres(..., use_phase=False)` 的实际历元数值对照，以及卫星对、`v/H/R` 数量、对称性、半正定性的单元测试。

验收：纯 RTD 不退化；RTD-TC 更新率不下降；目标窗口 H-RMSE 相对 P0 改善且不超过纯 RTD `1.15` 倍。

### R2：公共星座/频率/观测筛选对齐

在 R1 未解释问题时，固定 GPS-only，再逐项验证 `nf`、`freq_ix`、CNR、仰角和 base/rover 配对。BDS/GLO/GAL 只能在 GPS-only 基线通过后单独加入，不能混入 RTD-TC 首轮结论。

### R3：TC 协方差运行点

冻结量测构造后，单变量测试 `vel_psd`、`vel_var_floor`、初始速度方差；记录 `P[pos,vel]`、`K_vel` 和更新间速度误差。不得用参数把创新拒绝或姿态发散隐藏起来。

### R4：初始化和姿态可观测性

仅在量测/协方差通过后，检查初始位置、RFU→FRD、动态航向、零杆臂下 yaw/pitch 可观测性；候选包括 Doppler 速度量测、安装角/杆臂模型或 NHC，但每项必须另建实验，不得与 R1/R3 叠加。

### R5：门限与 fallback

最后才测试 `maxcode`、创新拒绝、SPP fallback 和降级门限。必须同时报告被拒量测类型、首次拒绝时间和 fallback 次数，禁止仅凭 RMSE 选择宽松门限。

## 10. Phase 5：最终验收

每个候选必须在以下三层复核：

| 层 | 结果 | 必报内容 |
|---|---|---|
| G0 | 原始纯 RTD | E/N/U、H/3D RMS、最大误差、有效历元、卫星数、质量 |
| G1 | 同 GNSS 参数纯 RTD | E/N/U、H/3D RMS、最大误差、有效历元、卫星数、质量 |
| T0-U | RTD-TC 更新点 | 更新率、Qins、innovation、P/S/K、位置/速度/姿态反馈 |
| T0-I | RTD-TC 整数秒代表点 | E/N/U、H/3D RMS、更新时刻关联、最大误差 |
| T0-A | RTD-TC 全部点 | 传播段误差、更新间增长、首次发散、降级/重启 |

同时与 ignav RTD-TC（若可运行）和 RTKLIB/纯 RTD 参考比较，但只在输入、星座、频点和评估口径一致时形成算法结论。ignav 高频输出不得逐行硬匹配，应使用整数秒事件和相同时间区间。最差 100 s 窗口必须由 P0 基线按预先固定的规则一次性选定，后续候选不得重新挑选窗口。

最终通过需要满足：

- G0 不退化；
- T0-U、T0-I、T0-A 的水平与高程 RMS 分别相对 G1 不恶化；目标窗口水平和高程 RMS 的增量均不超过 `0.03 m` 或 `15%`（取较宽松者），并单列 G0 与 G1 的配置差异；
- 高程 RMS 不出现新的系统偏差或明显增大；
- 有效更新率、最大误差、首次发散时间和降级次数不恶化；
- 所有 P/S 矩阵有限、对称、半正定，诊断可复现；
- 至少一次独立回放和完整测试集通过。

## 12. 回退、停点和请示规则

立即回退到最近通过基线并保存证据：目标/最差/全段任一关键精度恶化、纯 RTD 退化、更新率下降、出现错误跳变、量测被大量拒绝、P/S 非正定或实验无法归因。

标记 `ASK-EVAL`：输出列/Qins 语义无法可靠识别，必须修改评估脚本或输出格式才能继续。

标记 `ASK-MEAS`：需要改变 `RtdTcMeas` 接口、状态向量、协方差传播、RTKLIB 核心或 GNSS 观测定义才能继续，先提交诊断和最小复现，不擅自修改生产代码。

标记 `ASK-OBS`：采用 RTKLIB 的观测/频率策略后，纯 RTD 或 RTD-TC 反而恶化；回退并报告逐卫星映射差异，不得继续调 INS 噪声。

若连续两轮只改善目标窗口而损害全段，停止参数搜索，回到输入、时间、卫星集合和姿态可观测性审计。
