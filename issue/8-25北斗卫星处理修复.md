# 2026-08-25 北斗卫星处理修复：Data19 纯 GNSS 对照与诊断指南

## 1. 目的、范围和完成条件

本任务以 `Data19_20201214_HG4930_CAR_Opensky` 的 RINEX 数据为唯一实验数据，
把 gipylib 的北斗处理与本地 RTKLIB `rnx2rtkp` 做可复现、逐层的对照。目标不是先
让最终轨迹看起来接近，而是找到 BDS 与 GPS 从何处开始不一致，并以证据支持后续的
源码修复。

本阶段只新增诊断配置、运行与比较脚本，以及其结果报告；不得修改下列算法源文件：

```text
src/core/gnss/rtklib/{rinex.py,ephemeris.py,pntpos.py,rtkpos.py,rtkcmn.py}
src/core/gnss/rtklib_config_adapter.py
```

特别要验证提交 `b039a7b` 中 BDS GEO 卫星坐标旋转的实现。最终定位误差改善不能单独
证明 GEO 修复正确，必须有同一时刻、同一颗卫星的位置和钟差对照。

完成标准：

1. 9 个纯 GNSS 实验均生成 gipylib 与 rnx2rtkp 的解、配置快照、日志和输入 SHA-256。
2. 每个 BDS-only 与 GPS+BDS 实验都生成观测、星历、卫星状态、改正/残差、解算状态和
   最终位置的可机读比较结果。
3. 对每一个超过阈值的字段，报告必须给出最早的 `(week, sow, satellite, frequency)`、
   两侧数值、差值、上游阶段和候选源码位置；不允许只给 RMSE。
4. 在所有底层门槛通过前，禁止据最终 RTK 轨迹、固定率或真值误差修改调参或算法。

本轮不涉及 IMU、杆臂、RFU 姿态、RTK-TC 或 RTK-LC。现有
`experiment/build_configs.py` 和 `gipylib-bds-*.yaml` 服务于此前的 INS 实验；其纯
RTK 输出可作为参考资料，但**不是**本 3 x 3 矩阵的配置来源。

## 2. 固定实验条件

所有实验使用广播星历，先排除 SP3/CLK 差异。输入和约束如下：

```text
ROVE.20O                    rover observation
BASE.20o                    base observation
brdm3490.20p                mixed broadcast navigation
base ECEF (m)               -2279978.2868, 5008244.0572, 3214109.8574
time system                 GPST, 1 Hz RINEX epochs
ephemeris                   broadcast only
frequency                   two frequency: GPS L1/L2, BDS B1I/B2I
elevation mask              10 deg (same in both programs)
troposphere / ionosphere    freeze to one explicitly documented pair per run
receiver/base antenna       no unmodelled offset; base coordinate is fixed above
```

Rover and base RINEX headers contain BDS `C1I/L1I` and `C7I/L7I`.
`C1I/L1I` must resolve to B1I = `1561.098 MHz` and `C7I/L7I` to B2I/B2b =
`1207.14 MHz`; BDS B1C/B2a/B3 or GPS frequency must never be silently used.

The constellation translation is fixed:

| Case tag | Constellation | rnx2rtkp `pos1-navsys` | gipylib `gnss_t` |
| --- | --- | ---: | --- |
| `gps` | GPS | `1` | `[GPS]` |
| `bds` | BDS | `32` | `[BDS]` |
| `gpsbds` | GPS+BDS | `33` | `[GPS, BDS]` |

`rnx2rtkp` calls code-only relative positioning `dgps`; gipylib calls the
corresponding code-relative mode `rtd`. This is a nomenclature mapping, not an
optional mode substitution: the generated comparison manifest must record
`reference_mode=dgps` and `gipylib_mode=rtd` for these three cases.

2. BDS-only SPP establishes time, signal, BDS clock and code-bias correctness.

first common epoch, then the full overlap. A slice failure is a blocker; full
data must not be used to average out the first divergence.

## 7. Layered comparison, tolerances and stop rules

All comparison joins use `(GPST week, sow rounded to 1 ms, satellite, receiver,
frequency index)`. Times outside a 1 ms match are separately reported rather
than nearest-neighbour matched. Comparison output always includes `left`,
`right`, `delta`, tolerance, pass/fail and source file/line identifier.

| Layer | Inputs and required checks | Initial gate | Failure action |
| --- | --- | --- | --- |
| A. RINEX | Epoch count/time, system/PRN, C1I/L1I/C7I/L7I values, LLI/SNR, rover/base common set | identical time and satellite IDs; raw values exact to RINEX precision | stop; fix parser/selection before orbit work |
| B. Signal | selected code/phase column, B1I/B2I frequency and wavelength | frequency exact within 1 Hz; wavelength within `1e-9 m` | stop; inspect `sig_tbl`, frequency indices and RINEX mapping |
| C. Time/eph | BDT-to-GPST week, TOE/TOC, selected IODE, health, BDS GEO/IGSO/MEO class | week/TOE equal; health equal | stop; inspect `rinex.py` time conversion and ephemeris selection |
| D. SV state | broadcast satellite ECEF and clock at transmit time, including C01-C05 GEO | position norm delta <= `1e-3 m`; clock <= `1e-11 s` | stop; inspect GEO formula, Earth rotation and clock polynomial |
| E. Code model | geometric range, satellite clock, TGD, ionosphere/troposphere, SPP code residual | each named correction <= `1e-3 m`; residual delta <= `1e-2 m` | stop; inspect `gettgd`, `prange`, clocks and receiver clock state |
| F. DGPS | common rover/base BDS set, zero-difference code residual and relative code innovation | common set exact; innovation delta <= `1e-2 m` | stop; inspect epoch pairing/base coordinate/differencing |
| G. RTK | phase wavelength, zero/DD residual, reference satellite by constellation/frequency, slip/rejection, float ambiguity | same reference and valid set; DD delta <= `1e-3 m` before filter update | stop; inspect `rtkpos.py` DD and ambiguity state |
| H. Solution | ECEF solution, status, NSAT, age, ratio, truth ENU error | SPP/DGPS position delta <= `0.10 m`; RTK float <= `0.02 m`; fixed <= `0.01 m` | root cause must be in a prior failed layer unless all passed |

These are initial diagnostic gates, not claimed physical accuracy requirements.
If a documented implementation difference makes a gate inapplicable, record the
exact model difference, rerun a controlled configuration that removes it, and
do not relax a threshold globally.

For BDS GEO, the D-layer comparison must explicitly contain C01-C05 when
visible. For BDS-3, classify each PRN from the navigation file and report every
visible BDS-3 satellite independently; a successful aggregate BDS-only result
does not validate BDS-3 handling.

`compare_solution_series.py` parses `solution.pos` on both sides, aligns GPST,

the comparison or filter.

per case containing input hashes, epochs, usable satellites by system, first
failing layer, first failing BDS satellite/time, all gate counts, solution
statistics and links to artifacts. A case can be `PASS` only if all applicable
layers A-H passed; `INCONCLUSIVE` is not `PASS`.

## 9. Minimal-reproducer and root-cause workflow

When any BDS case fails:

1. Freeze generated configs, executable hashes and the first failing 120-second
   slice in `results/manifest.json`.
2. Reduce to one epoch, one failing BDS satellite and, for relative modes, the
   matching rover/base observations. Add one known-good GPS or BDS satellite
   only if the algorithm requires geometry.
3. Compare layers A through D before opening a filter trace. In particular,
   separate BDT/GPST, PRN-to-satellite conversion, selected ephemeris, BDS
   GEO class and satellite clock from pseudorange processing.
4. If D passes, compare the named code-model terms in E. Treat TGD as a
   frequency-dependent correction; record the code selection that chooses it.
5. If E passes, move to F then G. Capture reference satellite selection and
   wavelength before examining AR ratio or final trajectory.
6. File the cause under exactly one primary class: `rinex-signal`, `time`,
   `ephemeris`, `geo-orbit`, `clock-tgd`, `spp-clock`, `relative-code`,
   `phase-wavelength`, `dd-reference`, `cycle-slip-ar`, or `mixed-system`.
   Any secondary interaction is recorded separately.
7. Only then draft a small code fix and a regression test that fails before the
   fix. The regression must include the first failing BDS PRN/epoch or a
   synthetic case that preserves its mathematical condition.

## 执行记录（2026-08-25，两个 bug 修复完成）

### Bug 1: BDS GEO 卫星旋转修正缺失

**文件**: `src/core/gnss/rtklib/ephemeris.py` `eph2pos()`

**根因**: RTKLIB C `ephemeris.c` 对 BDS GEO（PRN≤5 或 ≥59）有专门的旋转修正
（5° 倾角偏移 + 无标准地球自转修正），gipylib 完全缺失。

**修复**: 增加 BDS GEO 分支:
```python
if sys == uGNSS.BDS and (prn <= 5 or prn >= 59):
    O = eph.OMG0 + eph.OMGd * tk - omge * eph.toes  # 无 (OMGd-omge)
    ...
    rs = [xg*coso+yg*sino*COS_5+zg*sino*SIN_5, ...]
```

### Bug 2: BDS 星间钟偏 (ISB) 参数缺失

**文件**: `src/core/gnss/rtklib/pntpos.py` `rescode()`

**根因**: SPP 估计 GPS/GLO/GAL 三个接收机钟偏参数 (NX=6)，
但 BDS 没有独立的钟偏参数。BDS 伪距残差包含未建模的 BDT-GPST 偏差，
导致 SPP 最小二乘收敛到错误位置（BDS-only SPP 误差 >100km）。

**修复**: NX 6→7，增加 BDS ISB 参数 (x[6]):
```python
elif sys == uGNSS.BDS:
    v[nv] -= x[6]
    H[nv, 6] = 1.0
    mask[3] = 1
```

|---|---|---|
| GPS+BDS RTK 解算数 | 31 | **10084** |
| GPS+BDS FIX 率 | 0% | **64.1%** |
| GPS+BDS H RMSE (绝对) | km 级 | **454cm**（优于 RTKLIB 516cm）|

### Bug 3: BDT→GPST 时标缺失（rinex.py 星历解码）

RINEX BDS 星历时间标签为 BDT，解码只做了周转换(+1356)却漏加 14s。
tk 偏 14s → MEO 卫星位置沿迹误差 ~50km（SP3 对照实测 37.8km），
SPP 发散而 RTK 双差不受影响（轨道误差被差分吸收）。
修复: `eph.toc/toe/tot = timeadd(..., 14.0)`（对齐 RTKLIB C bdt2gpst, rinex.c:1252-1258）。
**SP3 精确历元验证**: MEO/IGSO 37.8km→2.7m, GEO 620m→5.6m。

注意: 调试中发现线性插值 15min-SP3 本身引入 ~15km 弧差，
星历精度对照必须在 SP3 精确历元上做（勿插值）。

### Bug 4: 基站 RINEX 列映射错误（rinex.py decode_obs）

`f = i // (nsig//nband)` 假设观测列按"频点分块"排列；
BASE.20o 为"类型分组"(C,C,L,L,S,S) → P2/S1 映射错位:
基站 C7I 伪距丢失(→0)、S1I→0。后果链:
zdres 的 cnr_min 门限把基站 L1 整频丢弃 → 双差只剩 L2
→ L2 模糊度因基站 P2 缺失永远无法初始化(x=0,P=0)
→ KF 该状态增益为 0 但量测行仍进入 → 毒化浮点解 → FIX 率崩塌。
修复两层:
1. `BAND_SLOT` 表按信号频带号(第2字符)映射槽位, 回退位置启发式;
2. zdres_sat: S==0 视为"未记录"不剔除（对齐 RTKLIB snr mask 默认关闭）;
3. ddres: 相位双差要求两端模糊度状态已初始化(P>0), 否则跳过该行。

### maxinno 语义澄清

代码中 `nav.maxinno=[cfg.maxinno, cfg.maxcode]` — yaml 的 `maxinno`
只是**相位**双差门限, 伪距门限是独立的 `maxcode`。
RTKLIB C 默认 {phase:5, code:30}。相位门限=30 会放过未初始化模糊度行,
实测 FIX 率: mi30→2%, mi5/mi1→65%(修复前)/99.7%(修复后)。
**配置文件已按用户要求全局改 30; RTK 场景建议 5**（数据佐证见上）。

## 追加：TC 精度根因修复（IMU 时标系统滞后）

### 现象与定位过程
TC 输出 vs 天线真值恒定 H≈6m（GPS-only TC 同样 ~7m，排除 BDS 特有）。
排查链:
1. 符号翻转实验 → 发散 ⇒ 原 H/反馈符号正确;
2. 速度偏差仅 0.16 m/s ⇒ 非速度偏置;
3. 单历元模型一致性 mean=0.13m ⇒ 量测模型无系统差;
4. TC−SPP 差矢量零均值大抖动(std 4.5m) ⇒ 非固定偏移;
5. **时移扫描**: TC 内容相对时间戳滞后 ~0.8s（SPP/RTK 在 0s 最优 ⇒
   真值时基正确，问题在 TC 的 IMU 流）;
6. 起步时刻对比: 真值 95259.0 vs TC 95264.8;
7. 逐历元轨迹匹配: 中位滞后 −0.749s (std 0.33)。

### 根因
HG4930.imr 数据集本身 IMU 时标相对 GNSS/真值存在 ≈0.75–0.85s 系统滞后
(审计确认 CSV 忠实于 IMR 原始时戳, time_tag_bias=0 ⇒ 滞后来自数据采集端,
IE 生成真值时已自行修正)。INS 按"晚打点"的 IMU 积分, 状态内容落后于
其时间戳, GNSS 更新在此错误对齐下收敛到沿迹偏移的平衡点。

注意: 偏移必须施加于 **TcStream.feed_imu 喂入边界**; 在 formator 解码端
施加同量偏移实测无效(6.19m), 机制待查 — 已统一收口到喂入边界。

### 修复
新增配置 `ins.imu_time_offset_s` (默认 0, 不影响既有行为):
TcStream 构造时读取, feed_imu 入口 dataclasses.replace 平移时间戳。
Data19 三个 TC 配置设为 -0.85。

### 效果
| 配置 | H_med | H_rmse | U_med | U_std |
|---|---|---|---|---|
| TC 修复前 | 6.05 | 6.01 | +0.51 | 1.38 |
| **TC 修复后 (-0.85)** | **2.00** | **2.91** | +0.53 | ~1.4 |

剩余差距 (vs SPP 0.86m): 滞后非常数(std 0.33s, 机动段变化) +
SppTcMeas 单频伪距几何弱于 RTK。后续可做逐历元自适应时延或
启用 estimate_time_sync 在线估计。

### maxinno 最终裁定
全部配置恢复 5.0 (相位门限; 伪距门限独立为 maxcode=30)。
RTK GPS+BDS FIX=99.7% 即在该值下取得。
