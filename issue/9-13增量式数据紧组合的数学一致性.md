## 目标与不可变约束

目标是在同一 campus01 原始数据上证明或反证 gipylib 的增量 IMU RTK-TC
机械编排、测量构造和滤波更新与其声明的 ECEF/双差数学模型一致；只有在
证据定位到单一缺陷后才允许最小修复。所有实验必须保持：

- `armode=0`，不调用 LAMBDA、ratio、partial fix 或 hold；
- 原始 100 Hz IMU 流式消费；不重采样、不批量插值、不复制状态凑高频；
- 不改变观测权重、噪声、门限、truth 窗口或卫星选择来改善 RMS；
- 真值仍是 10 Hz truth-left 最近邻（`±0.051 s`），不插值真值；
- 每一条生产修复先有一个能在修复前失败的最小红测，且一次只改变一个已证实根因。

## 串行审查计划

### A. 观测图同构门禁（先于所有数学结论）

1. 解析 GREAT `CAMP-MSF.stage-trace.csv` 的 canonical PRN、candidate、accepted、
   rejected、band、track、reference 与 gipylib measurement JSONL 的 DD keys、
   exclusion reason、raw mapping。
2. 每个相同 SOW 和系统分别统计 `candidate / accepted / rejected / reference` 的
   集合交、差和语义差；内部 sat number 必须先转换为 RINEX PRN。
3. 输出首个不一致历元的原始信号、频段、剔除理由和 reference 选择。GREAT 的
   “retained satellite count”不得与 gipylib 的 DD 行数混为同一单位。
4. 验收：只有 candidate/accepted/reference 的定义与集合均被证明可比时，才能
   比较同一 DD 行的残差、Jacobian 和 R；否则把差异记录为输入/选择层缺口。

### B. 增量 IMU 流与 ECEF 机械编排门禁

1. 固化 `RateImuData -> IncrementImuData` 的前后样本流式约束：只有 previous/
   current/一个 GNSS 边界后半段，`dtheta/dvel/dt` 守恒。
2. 对 GNSS 落在增量内部、端点、区间外三种情况，证明 split 前后总增量和总 dt
   相等，且测量只消费一次。
3. 对每个实际 increment，断言机械编排使用 payload dt；状态转移 `Phi`、过程噪声
   `Q` 和 clock/ambiguity random walk 使用相同有效 dt。
4. 从同一名义状态做有限差分：验证 ECEF position/velocity/attitude 的单步增量
   与解析传播一致；反馈必须为 `nominal - error`，并在更新后保持协方差对称。
5. 验收：0.01 s 单步状态差、dt 守恒、GNSS exactly-once、P 对称误差均有自动化
   证据；未通过时禁止将误差归因于观测模型。

### C. RTK-TC 测量更新门禁

1. 为 code/phase 双差分别做 position、lever-arm、ambiguity Jacobian 有限差分；
   phase 的波长按每颗星/频段计算，GLO 必须使用频道。
2. 验证 reference satellite 的符号、观测排序和共享参考星引入的 R 非对角协方差；
   单频每系统只使用 slot 0。
3. 在真实 SOW 写出 pre/post 的状态、P 摘要、innovation、post-fit residual、DD key；
   独立重算 `r - H dx` 与更新结果。
4. 验收：`max|H-H_fd| <= 2e-3`、残差复算误差 `<=1e-5 m`、R 的共享 reference
   非对角项与 DD key 一一对应；所有失败均记录为可复现红测。

### D. 根因修复与回放

只在 A–C 找到单一可证伪根因后执行：红测 → 最小修复 → 局部回归 → 100 Hz
strict-float 重放 → truth-left 评估。每次提交必须分别通过 diff check 与代码审查，
并记录前后物理合同、输出 hash、行数、dt、Float/Fixed 计数和 RMS3D；连续三次
假设失败时停止修改并重新审查架构。
