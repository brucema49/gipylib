# gipylib 机械编排优化与状态传播对比计划

## 1. 任务范围与当前问题

当前观察是：`gipylib/data/rtk-ins紧组合.yaml` 生成的 `gipylib/data/output/RTKINS.rslt` 在 GNSS 测量更新后，后续高频机械编排结果相对 ignav 出现较大的位置、速度或姿态偏差。现阶段不能直接把它称为“机械编排公式错误”，因为观测更新、状态反馈、协方差传播和名义状态传播都可能在更新边界引入或放大偏差。

本文件只制定分析、评估、修改和回退指导，不修改任何 Python、C/C++、YAML、IMU、RINEX、输出结果或 ignav 源码。历史 `issue/8-11机械编排bug.md` 只作为背景索引，未在当前版本重新复现的旧结论不得直接写成根因。

### 1.1 与 `8-22` 已验证结果的衔接

`issue/8-22-rtktc详细对比.md` 已证明，先前约 `0.213 m` 的目标窗口误差并不能直接归因于机械编排：`gnss.prnbias=0.5` 会使载波模糊度协方差托底并退化为码级浮点，TC 使用 LC 的 `vel_psd=0.5` 又会冲掉 INS 的量测间记忆。当前机械编排调查必须以已验证的配置栈为起点：

- `data/rtk-ins紧组合.yaml`：`prnbias=0.03`、TC `vel_psd=0.001`；
- 8-22 已验证的 TC 浮点基线：目标窗口水平 RMSE 约 `0.071 m`、全段约 `0.254 m`；ignav 同窗口参考约 `0.057 m`；
- TC `armode>0` 只作为单独的 AR 分支记录，不能与机械编排基线混用；
- 若当前工作树、输入数据或输出结果与上述条件不一致，先建立 `B0-reg[Texp]` 回归记录，复现或解释差异后才能进入本计划的 Phase 1。

因此，后续机械编排实验默认冻结 `prnbias`、`vel_psd`、GNSS 观测筛选和 TC AR 状态。除非出现相对于 8-22 基线的回归，否则不得把这些参数重新作为机械编排候选。

## 2. 目标

1. 确定偏差首次出现于：
   - IMU 输入/时间间隔与单位；
   - 姿态、速度、位置名义机械编排；
   - `F/Phi/Q` 协方差传播；
   - GNSS 量测更新前后状态反馈；
   - 杆臂、时间同步或坐标/单位转换。
2. 建立 gipylib 与当前版本 ignav 的同历元、同坐标、同 IMU 区间对照，解释 ignav 的机械编排为何在更新点之间更平稳。
3. 形成可复现的机械编排量化指标：更新点误差、量测间传播误差、状态差异、首次异常历元和误差增长率。
4. 每次修改都必须经过统一精度评估；收益不明确或任一关键指标恶化时回退到上一通过版本。
5. 保持 `8-22` 已通过的纯 GNSS 与 TC 精度，区分“真值误差变差”和“与 ignav 的状态差异变大”这两个不同判据。

## 2.1 执行策略与选择理由

可选的调查路径如下：

| 路径 | 做法 | 优点 | 局限 |
|---|---|---|---|
| A：结果级对比 | 只运行 `mechanism-diff.py` 和位置精度脚本 | 快速发现时间段和误差方向 | 无法区分更新、传播、协方差和输入问题 |
| B：分层诊断（推荐） | 先纯 GNSS/TC 分流，再按 IMU、名义状态、更新、`F/Phi/Q` 逐层插桩 | 每一步都有可证伪判据，适合单变量回退 | 需要保留中间状态和统一时间索引 |
| C：完整参考复刻 | 直接逐项复刻 ignav 机械编排和协方差实现 | 可能最快达到数值接近 | 代价高，容易把输入或更新层差异误当公式差异 |

采用 B；只有 B 已证明差异位于某个公式或状态边界时，才使用 C 对该局部做对齐。A 只能作为初筛，不能作为修复依据。

## 3. 数据、代码和评估文件

### 3.1 gipylib

- 主配置：`gipylib/data/rtk-ins紧组合.yaml`
- 主结果：`gipylib/data/output/RTKINS.rslt`
- 真值：`gipylib/data/truth.csv`（1 Hz PVA；姿态字段和坐标定义须先核实）
- 现有结果差异脚本：`gipylib/data/plot/mechanism-diff.py`
- 统一位置评估脚本：`ignav-debug/a-cpt/plot/error_rtdtc.py`
- 参考轨迹脚本：`gipylib/data/plot/tra-neu.py`、`ignav-debug/a-cpt/plot/tra_neu.py`
- 状态评估脚本占位：`gipylib/data/plot/error-state.py` 当前为空文件，不能视为可用评估器；后续实现前先定义输入列、姿态约定、真值插值和统计掩码，并不得把 Qins 筛选当成 GNSS 更新识别。本轮不创建或修改该脚本。
- 结果级精度脚本：`gipylib/data/plot/error-rslt(1).py`；它可绘制全部历元，但历史实现可能只用 Qins=3 统计 RMS，必须同时输出“整数秒更新点”和“全部传播点”两套指标。

### 3.2 ignav

- 当前配置和输出必须使用同一版本、同一输入数据重新生成，不能把旧的纯 RTK 文件当作 INS-TC 机械编排参考。
- 配置参考：`ignav-debug/a-cpt/cpt-rtktc-gpsonly.conf` 或当前实际采用的等价配置。
- 输出/中间状态候选：`ignav-debug/a-cpt/output/*.rslt`、`*.stat`、trace 文件，以及 ignav `ins-gnss`/`ins` 模块可输出的 `$POSI`、`$VELACCI`、`$ATT`、`$GBIAS`、`$ABIAS` 等状态。
- 若现有输出只有 1 Hz 状态，必须明确它只能用于更新点状态对比，不能直接证明 100 Hz 量测间传播没有漂移；需要规划 trace 或等价高频状态输出后再做高频对照。

### 3.3 现有脚本能力边界

`mechanism-diff.py` 当前读取两个 `.rslt` 的位置、速度和质量字段，在共同 GPS 时间上计算 ECEF/ENU 差异；它不读取 IMU、不区分更新前后、不比较姿态/零偏/P 矩阵，也不使用真值。因此它只能作为结果级初筛，不能单独证明机械编排公式或零偏是根因。

`.rslt` 的列位置、LLH/ECEF 类型、速度参考系和 Q/Qins 含义必须从文件头及生成代码确认。当前脚本对参考文件按 ECEF、对评估文件按 LLH 读取，并按固定列索引读取速度；任何输入格式改变都必须先修正评估配置或记录为不可比，不能静默解析。

建议按以下层级保存证据：

1. **L0 真值误差**：`error_rtdtc.py`、`error-rslt(1).py` 的 E/N/U、水平和 3D 指标；
2. **L1 结果差异**：`mechanism-diff.py` 的 gipylib-ignav ECEF/ENU 位置速度差；
3. **L2 状态差异**：后续状态诊断接口（`error-state.py` 目前为空占位）应覆盖姿态、零偏、P 和更新前后状态；
4. **L3 传播单步差异**：IMU 两历元间 `dt`、补偿增量、姿态/速度/位置增量和 `Phi/Q`。

只有 L3 或 L2 的差异与 L0/L1 的首次异常历元一致时，才可以提出机械编排或协方差修复候选。

## 4. 统一时间、坐标和采样口径

### 4.1 时间记号

- `Tdata`：数据历元时间，统一记录 GPS Week + SOW；必要时附 GPST、UTC 和 Unix 秒。用于 IMU 样本、GNSS 更新、状态输出、首次异常和恢复时刻。
- `Texp`：实验操作时间，使用 `YYYY-MM-DD HH:MM:SS+08:00`。用于配置快照、命令执行、评估、回退和报告生成。
- `B0[Texp]`、`CAND-xx[Texp]`、`EVAL-xx[Texp]`、`RB-xx[Texp]`、`ASK-xx[Texp]` 分别表示基线、候选、评估、回退和请示；`first_bad[Tdata]` 表示首次异常历元。

### 4.2 必须统一的口径

1. 确认两套程序使用同一修正后的 IMU 数据、GPS week/SOW 和时间转换；不重复加闰秒。
2. 每个 GNSS 更新点使用时间上最近的整数 GPS 秒结果作为主要评价点，其余高频点单独归入传播点；Q/Qins 只作辅助属性，不能作为唯一更新识别条件。
3. 位置统一转 ECEF 后再计算 ENU；明确 ENU 原点、E/N/U 顺序、Up 符号、LLH 高度类型和 WGS84 参数。
4. 速度统一为 ECEF 或 ENU 之一；不得将 ignav 的 ENU 速度、ECEF 速度和 body 速度混比。
5. 姿态统一为同一方向余弦矩阵约定（如 `C_b^e` 或 `C_b^n`），比较前转换到同一导航系，并用姿态相对旋转角及 roll/pitch/yaw 误差同时报告，避免欧拉角跳变误判。
6. 所有匹配报告 `Tdata_start/end`、时间差、有效样本数、未匹配数和 `first_bad[Tdata]`。
7. 更新点集合由 GPS SOW 与整数秒的距离阈值定义，并记录阈值、匹配误差和重复匹配数；Q/Qins 仅作为结果标签保留。

## 5. 基线评估与收益纪律

### 5.1 B0 基线

在任何修改前冻结 `B0[Texp]`：配置、代码版本、输入数据、命令、评估脚本版本和输出目录。依次完成：

1. 纯 GNSS RTD/RTK 结果评估，确认机械编排调查没有改变 GNSS 基线；
2. RTK/RTD-INS-TC 统一位置评估：E/N/U、水平、3D RMSE、最大误差、95% 分位、整数秒点和全量点；
3. 结果级 `mechanism-diff.py` 对比；
4. 更新点与传播点分段统计；
5. 若状态数据可用，比较位置、速度、姿态、陀螺零偏、加计零偏和协方差对角线。
6. 将 B0 的重复运行差异作为评估噪声基准；若重复性未量化，不得凭小数点后三位的变化宣称收益。

`B0` 必须至少记录以下预期量级（实际值以同一脚本重跑为准）：目标窗口 TC 水平 RMSE 约 `0.071 m`、全段约 `0.254 m`。如果重跑明显偏离，优先做回归调查，不得直接进入机械编排调参。

### 5.2 每次候选修改的强制流程

1. 记录 `CAND-xx[Texp]`，只修改一个变量或一个严格相关变量族。
2. 先运行纯 GNSS，再运行 TC；修改前后使用同一评估脚本、真值、时间窗、匹配规则和坐标转换。
3. 比较更新点和传播点，不得只看总 RMSE 或单张图。
4. 只有主要机械编排指标改善、更新点精度不退化、纯 GNSS 不退化且没有新的发散，候选才可成为下一基线。
5. 任一关键指标恶化、出现新的跳变、有效更新减少或状态协方差非正定，立即保留失败产物并回退到上一通过版本，记录 `RB-xx[Texp]`。
6. 若修改是为了对齐 ignav，但对齐后结果仍恶化，暂停自主修改，记录 `ASK-xx[Texp]`，向用户报告后留待后续处理。

## 6. 分阶段分析计划

### Phase 0：复现现象和确认“漂移”定义

- 在固定窗口（优先 GPS Week 2046、SOW `359000-359100`，另保留完整重叠区间）复跑当前 gipylib 与当前 ignav。
- 用 `mechanism-diff.py` 报告位置/速度差异，但同时区分：更新后瞬时跳变、更新间增长、恒定偏置和全段累积漂移。
- 对每个更新间隔输出 `dt`、起点/终点位置速度姿态差、传播点最大误差、斜率和 p95。
- 若偏差在更新瞬间出现，优先进入 Phase 3；若更新后逐步增长，优先进入 Phase 2；不能预先假定是姿态或零偏。
- 分流判据：纯 GNSS 与 TC 同时变差时先查 GNSS/输入；纯 GNSS 正常而 TC 在更新后跳变时查 Phase 3；更新点正常但点间误差单调增长时查 Phase 2；位置误差正常而 P/K 或零偏异常时查 Phase 4。分流结论必须写入 `first-bad.md`。

### Phase 1：输入和时间间隔核对

- 统计 IMU 时间戳的首尾范围、`dt` 中位数/p01/p99、重复/非正/异常间隔、丢样和跨越 GNSS 更新的样本数。
- 核对 gyro、accel 是速率还是增量，单位是否分别为 rad/s、m/s²，RFU/FRD 转换是否只执行一次，零偏单位是否一致。
- 对当前配置明确核对 `imu_format=euroc` 的 Unix 纳秒到 GPST 转换、100 Hz 采样率和 `imu_coordinate_system=RFU` 到 FRD 的单次转换；同一数据不得同时按 GPST 和 Unix 时间再校正一次。
- 检查 `InsUpdate` 使用的当前样本与上一样本时间边界、无效 dt 的处理、锥补/划桨历史量是否跨越 GNSS 更新正确延续。
- 对无效或超限 `dt` 单独记录“跳过传播”和“时间边界前移”事件，并与 ignav 的处理语义对齐；不能用跨越无效区间的大 dt 继续积分。
- 该阶段只读诊断；若发现输入问题，先以独立输入修正实验评估，不与机械编排公式修改混合。

### Phase 2：名义机械编排逐项对照

使用相同初始状态、相同 IMU 区间和相同 dt，逐项对照 gipylib `src/core/ins/ins_update.py`、`src/core/ins/transfer_matrix.py` 与 ignav `src/ins-gnss/ins.cc`、`src/ins-gnss/ins-back-mech.cc`、`src/ins-gnss/ins-gnss-tc.cc`、`src/ins-gnss/ins-gnss.cc` 中的 `updateins*`、`rotscull_corr`、`propinss`、`precPhi`：

1. **姿态**：陀螺零偏扣除、锥补、地球自转补偿、`C_b^e` 更新顺序、Rodrigues/四元数归一化和 DCM 正交性。
2. **速度**：比力投影、旋转补偿、划桨补偿、地球重力、科氏项、ECEF 旋转和速度更新顺序。
3. **位置**：梯形/中点积分、天线/IMU 位置关系、位置更新使用的前后速度。
4. **状态保存**：上一增量、上一时间、当前比力/角速度、姿态矩阵和四元数是否在相同阶段更新。

每项必须输出一阶中间量和累计量：`dtheta_comp`、`dvel_comp`、锥补、旋转补偿、划桨补偿、重力、科氏、`C_ee`、`C_b^e`、`delta_v`、`delta_r`。先做单步差异，再做 1 s、10 s 累计差异，防止只看最终位置。

### Phase 3：GNSS 更新、反馈和杆臂边界

- 在每个整数秒更新点保存更新前状态、GNSS 量测、H/v/R、Kalman 增益、更新后状态和反馈增量。
- 明确偏差首次出现在“更新前传播”“量测更新”“反馈后第一步”还是“后续传播”。
- 核对误差状态符号、位置/速度/姿态反馈、ECEF/NED 转换、杆臂位置和杆臂速度项、时间同步项，以及 GNSS 天线位置与 IMU 位置使用是否一致。
- 对无杆臂、固定杆臂、在线估计杆臂分别做独立候选；每个候选先评估纯 GNSS，再评估 TC。
- 若更新后立即出现稳定位置/速度台阶，优先核查 H、残差符号、量测坐标和反馈；不要把它归入“机械编排漂移”。

### Phase 4：F/Phi/Q 与协方差耦合

- 对比 `src/core/ins/transfer_matrix.py` 与 ignav 的 F、Phi、G、Q 构造，逐块检查位置-速度、速度-姿态、速度-加计零偏、姿态-陀螺零偏、Coriolis、重力梯度和可选状态块。
- 检查 `pos_psd`、`vel_psd`、零偏随机游走和时间同步随机游走是否按 TC/LC 语义分别使用；不得把 LC 的经验值直接带入 TC。
- 记录每次更新前后 P 对角线、相关项、最小特征值/Cholesky 状态和 Kalman 增益，区分“P 膨胀导致状态被错误量测拉偏”和“P 坍缩导致 IMU 状态无法修正”。
- 协方差候选的收益必须同时体现在传播点误差、更新点误差和数值正定性上。
- 当前已验证的 TC `vel_psd=0.001` 属于组合协方差基线，不等于名义机械编排公式；若需重新扫描，必须单独标记为 `COV-*`，不能与 `MECH-*` 候选混写。

### Phase 5：ignav 中间状态对照

- 根据 ignav 当前版本实现，增加只读 trace/状态输出规划，至少覆盖更新点的 ECEF 位置速度、姿态、gyro/accel bias、杆臂/时间同步状态、更新前后残差和质量标志。
- 参考 `ignav-debug/issue/8-21.md` 和 `issue/8-22-rtktc详细对比.md` 的历史产物，先确认输出对应当前 GPS-only INS-TC 配置；旧纯 RTK 或 Qins=0 结果不得升级为机械编排金标准。
- 记录 ignav 的状态定义、坐标系、单位、输出频率和天线/IMU参考点；不能只按字段名直接解析。
- 对 1 Hz 更新点使用真值评估姿态、位置和速度；零偏无直接真值时只做 gipylib/ignav 相对比较，不宣称绝对误差。
- 对 100 Hz 传播段优先比较两套程序的相邻状态增量和同一更新区间的累计误差；若 ignav 没有高频状态，必须标记“无法严格比较量测间漂移”，不能用 1 Hz 结果代替。

### Phase 6：最终验证与交付

- 以最新通过基线重复目标窗口和全段评估。
- 结果中同时给出：真值误差、gipylib-ignav 状态差、更新点指标、传播点指标、首次异常 `first_bad[Tdata]`、配置/实验时间 `Texp`。
- 只有传播点误差、更新点误差和数值稳定性均达到目标，才可称为机械编排优化完成；若只改善某一窗口或某一状态，必须明确剩余风险。
- 当前验收下限：TC 目标窗口水平 RMSE 不得劣于已通过 B0（约 `0.071 m`），全段不得劣于约 `0.254 m`；若候选旨在改善传播差异，必须在不突破这两个真值误差门槛的前提下，使传播区间指标有可重复改善。启用新 AR、杆臂或时间同步状态时另建分支验收。

## 7. 建议的诊断输出格式

## 8. 当前不应直接采用的结论

- 不能仅凭 `mechanism-diff.py` 的位置/速度曲线认定姿态或零偏是根因。
- 不能把旧的 ignav 纯 RTK 输出当作当前 ignav INS-TC 机械编排金标准。
- 不能把 1 Hz ignav 状态与 100 Hz gipylib 传播点直接逐行比较后宣称传播一致或不一致。
- 不能在没有修改前/修改后精度评估的情况下调整姿态、零偏、杆臂、过程噪声或反馈符号。
- 不能把一次短窗口改善推广为全段结论。
- 不能把 `8-22` 已解决的 `prnbias`、TC `vel_psd` 或模糊度实现问题，在未证明回归前重新包装成机械编排根因。
- 不能把“与 ignav 更接近”当作唯一收益；真值误差恶化时，即使状态差异变小也必须回退。
