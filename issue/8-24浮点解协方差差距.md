# gipylib 与 ignav 浮点解协方差差距交接计划

## 1. 任务范围与交接关系

本文承接 `issue/8-24ba优化.md` 未完成的 H5/Phase E：解释 MECH-16 后仍存在的 E 向半周期速度振荡，以及 GNSS 浮点残差、模糊度协方差、参考星切换和 TC 状态反馈之间的关系。

当前目标不是继续调整 ba、姿态初值或 `vel_var_floor` 来压低误差，而是先判断 gipylib 浮点 RTK/RTK-TC 的协方差与 ignav 是否存在可复现的结构差距，并定位该差距是否通过位置-模糊度交叉协方差传递到 INS 速度、姿态和 ba 状态。

本轮只新增本规划文件；不修改 Python、C/C++、YAML、RINEX、IMU、结果文件、评估脚本或 ignav 配置。后续执行中若需要新增诊断字段、脚本或修改代码，必须先按本文的阶段门控完成证据链，再单独提出修改计划。

## 2. 已知基线与待解释现象

`FINAL4/MECH-16[Texp=2026-08-24 04:40]` 是正式回归基线：

| 指标 | FINAL4/MECH-16 |
|---|---:|
| 目标窗口水平 RMSE（SOW `359000--359100`） | `0.0394 m` |
| 全段水平 RMSE（约 SOW `357460--359815`） | `0.2595 m` |
| 传播速度 RMSE | `0.099 m/s` |
| 量测间速度增长（约 100 s） | `8.0 cm/s` |

MECH-16 已消除 `vel_psd` 人工注入，使用已有 `ins.vel_var_floor=3e-4 m²/s²` 保持速度协方差运行点。相较早期基线，位置和量测间速度均已改善；但残余仍表现为 E 向约 `±3--4 cm/s` 半周期振荡，显著高于 ignav 量测间约 `2--4 cm/s` 的水平。

8-23 已排除名义机械编排公式：同初始状态、同 IMU 的 100 s 回放中，gipylib `InsUpdate` 与 ignav `updateins()` 累计速度差仅约 `6.6e-6 m/s`。因此后续优先检查 GNSS 浮点量测给出的状态修正和协方差，而不是重开机械编排公式、ba 人工标定或姿态手工补偿。

## 3. 核心问题与可证伪假设

### 3.1 核心问题

在严格相同的时间、卫星、频点、浮点模式和坐标口径下，gipylib 的以下量是否与 ignav/RTKLIB 参考存在系统性差异：

- 位置、速度与模糊度的后验方差及交叉协方差；
- 相位/伪距残差、创新协方差 `S`、量测权重 `R` 和拒绝事件；
- 参考星、共同可见星、周跳/失锁和模糊度重置；
- 从 GNSS 模糊度块到 INS 位置、速度、姿态、ba 的 Kalman 增益与反馈。

不能只比较 `P_amb` 的中位数或输出位置标准差。模糊度状态的单位、单差/双差定义、频点顺序、参考星和状态重参数化都可能不同；只有在同历元、同卫星对、同频点且转换到相同 DD 定义后，矩阵数值才可比较。

### 3.2 H-F1：浮点模糊度过程噪声或初始化使 `P_amb` 处于错误运行点

gipylib TC 每个 IMU 步按 `prnbias²·dt` 增长已初始化的模糊度对角；其模糊度状态通过 `sync_tc_ambiguities_with_rtklib()` 与 `udbias()` 同步。需验证时间间隔、单位、槽位初始化/清零和随机游走是否与纯 RTK 及 ignav 的 `stats-prnbias=0.03` 语义一致。

证伪条件：在相同浮点历元、同一 DD 参数化后，`P_amb`、相位残差和位置不确定度的量级、变化率均接近参考，且没有异常重置或僵尸槽位残留；此时不把 H-F1 作为后续修改方向。

### 3.3 H-F2：位置-模糊度交叉协方差不足或不一致，导致浮点量测不能正确反馈 INS

TC 量测诊断已记录 `pre_pos_amb_cov_norm`、`pre_amb_var_median`、`post_amb_var_median`、`h_amb_max` 和 `k_amb_norm`。若位置-模糊度耦合长期接近零、在参考星切换后突变，或与位置/速度反馈峰值不一致，则 GNSS 浮点更新可能无法将相位信息传递给 INS，或会把错误修正传到 E 向速度。

证伪条件：上述量与共同可见卫星数、相位残差和 `K_pos/K_vel` 呈合理连续关系，且参考星/周跳事件前后无异常断裂；此时转查 H-F3/H-F4。

### 3.4 H-F3：参考星切换、周跳或观测筛选导致 DD 状态重参数化不连续

参考星更换本身不必然是错误，但切换后等价 DD 状态和协方差必须完成一致变换。若仅清零局部槽位、状态槽位映射不同步，或将旧参考星的协方差直接解释为新参考星 DD 协方差，浮点位置会出现缓变或半周期偏差。

证伪条件：每个切换时刻的共同卫星集合、参考星、DD 变换、模糊度重置、残差和位置反馈均可闭环解释，且无只在 gipylib 出现的异常跳变或方差塌缩。

### 3.5 H-F4：量测 `R`/创新 `S` 或后验检验差异造成错误浮点反馈

即使 `P_amb` 正常，载波/伪距权重、卫星高度角、卫星系统因子、残差拒绝或 post-fit 门控不同，也会改变 `S=H·P·Hᵀ+R`、`K` 和位置/速度反馈。应确认残余 E 向振荡与 innovation、`S`、相位可用数、拒绝和降级事件是否同相。

证伪条件：在相同观测集合下，gipylib 与参考的相位/伪距残差统计、接受率及浮点位置标准差没有显著差异，且 E 向振荡不与任何量测事件相关；此时 GNSS 浮点层不能解释残余，回到 `8-24ba优化.md` 的姿态可观测性方向。

## 4. 数据、参考实现与统一评价口径

### 4.1 固定基线文件

- gipylib 主配置：`data/rtk-ins紧组合.yaml`；正式结果：`data/output/RTKINS.rslt`；真值：`data/truth.csv`。
- FINAL4 评估产物：`exp-8-23/eval/FINAL4-window/`、`exp-8-23/eval/FINAL4-full/`；历史诊断：`exp-8-23/logs/B0-diag.csv`、`exp-8-23/logs/COV06b-diag.csv`。
- gipylib 关键实现索引：`src/core/tc/tc_estimator.py`（INS/GNSS 分块传播、`P_amb` 随机游走、`vel_var_floor`），`src/core/tc/tc_measurement.py`（TC 与 `udbias()` 同步），`src/core/tc/tc_integration.py`（协方差/增益诊断和反馈边界），`src/core/gnss/rtklib/rtkpos.py`（纯 RTK 浮点、DD、模糊度和参考星管理）。
- ignav 参考配置：`../ignav-debug/a-cpt/cpt-rtktc-gpsonly.conf`；RTK 参考：`../ignav-debug/a-cpt/cpt-rtk-pure.conf`；核心实现：`../ignav-debug/src/ins-gnss/rtkpos.cc`、`../ignav-debug/src/ins-gnss/ins-gnss-tc.cc`。
- 统一精度评估：`../ignav-debug/a-cpt/plot/error_rtdtc.py`；姿态/状态评估：`data/plot/error-state.py`；姿态与 ENU 速度图：`data/plot/att-vel-error.py`；量测间差异：`data/plot/mechanism-diff.py`。

### 4.2 必须固定的比较条件

1. 浮点主线固定 `armode=0`，不得混入 AR/hold 的位置收益、伪量测或固定后协方差；纯 RTK float 与 RTK-TC float 分开分析。
2. 固定 GPS-only、相同 rover/base RINEX、广播星历、基站坐标、频点、截止高度角、时间系统、前向方向、真值插值和整数秒更新点规则。
3. 先比较同一 GNSS 更新历元，再分析该历元到下一更新历元的传播段；Qins 只作属性，更新点由 `update_flag` 或整数秒最近点规则确定。
4. DD 矩阵对比前，必须记录卫星号、频点、观测类型、参考星、状态类型（SD/DD）、单位（cycle/m）和状态排序。任一项不一致时，只能比较无参数化依赖的量，如残差分布、位置协方差特征值或归一化创新，不能直接逐元素比较 `P_amb`。
5. 每个矩阵样本都检查对称误差、最小特征值、Cholesky 可分解性、条件数和有限值；数值修补后的矩阵必须同时保留修补前诊断，不得把修补视为根因解决。

### 4.3 三层结果与门控顺序

| 层级 | 对象 | 目的 | 进入下一层的条件 |
|---|---|---|---|
| G0 | 纯 RTK float | 隔离 GNSS 浮点协方差，不受 INS 反馈影响 | 输出与诊断完整、无矩阵非正定/参数化不明 |
| G1 | RTK-TC float 更新点 | 判断联合滤波是否改变 GNSS 浮点协方差和位置反馈 | 已对齐 G0 同类事件与时间窗口 |
| G2 | RTK-TC float 传播段 | 关联 GNSS 反馈与 E/N/U 速度、姿态、ba 漂移 | 更新点差异和传播段指标可建立因果时间序列 |

未通过 G0 不进入 G1；未能解释 G1 的状态/协方差差异不进入 ba、姿态或 `P_vel` 参数实验；不能以 G2 某个短窗口变好绕过前两层。

## 5. 分阶段执行计划

### Phase F0：冻结 FINAL4 浮点协方差回归基线

1. 建立 `F0-COV[Texp]`：保存代码提交、`data/rtk-ins紧组合.yaml`、输入文件哈希、纯 RTK float 和 RTK-TC float 命令、输出、评估 JSON/CSV、诊断 CSV。
2. 先独立运行纯 RTK float，再运行 RTK-TC float；两者都用相同 `error_rtdtc.py` 报告目标窗口、预声明最差 100 s 机动窗口和全段的 E/N/U、水平/3D RMSE、有效历元与解状态。
3. 复现 FINAL4 TC 指标：目标窗口水平 `0.0394 m`、全段 `0.2595 m`、传播速度 RMSE `0.099 m/s`、量测间增长约 `8.0 cm/s`。若不能复现，先记录 `RB-F0[Texp]` 并处理回归，不进入后续阶段。
4. 对每个 GNSS 更新点生成统一索引：`week,sow,Tdata,mode,update_flag,solution_status,n_sat,n_phase,n_code,reference_satellite`。不存在的字段必须明确标为“参考输出未提供”，不能以猜测值补齐。

### Phase F1：纯 RTK float 的协方差和浮点质量对照

目标是先判断 gipylib 纯 GNSS 浮点链路是否已存在协方差差距。

1. 用 `armode=0` 运行 gipylib 纯 RTK float、ignav `cpt-rtk-pure.conf` 的纯 RTK float；必要时以 `../ignav-debug/tools/rtklib` 的 RTKLIB C float 作为第三方交叉参考，但不得把不同配置的结果混入同一结论。
2. 对相同更新历元分段统计：位置 ECEF/ENU 协方差或输出标准差、位置误差、相位/伪距残差 RMS、观测数、共同卫星数、相位有效数、拒绝数、周跳数、重初始化数、参考星切换数和 float 解比例。
3. 对共同卫星、同频点、同参考星的 DD 量，比较有效模糊度数量、状态值、方差、相关系数、最小特征值和条件数；若状态定义无法对齐，退化为比较每历元 `P_amb` 有效槽位中位数/分位数、位置方差和残差，而不做逐元素结论。
4. 标记 `first_cov_bad[Tdata]`：首次出现 gipylib 与参考在同类量上显著偏离的历元，同时保存前后至少一个 GNSS 周期的卫星集合、参考星、残差、方差和解状态。
5. 判定：若纯 RTK float 已出现同方向的协方差异常或 E/N 漂移，冻结 INS 相关候选并优先进入 Phase F2；若纯 RTK float 正常但 TC 异常，直接进入 Phase F3。

### Phase F2：模糊度时间更新与参考星重参数化审计

1. 沿 `src/core/gnss/rtklib/rtkpos.py` 的 `udbias()`、DD 构造、参考星选择、模糊度重置和 `src/core/tc/tc_measurement.py` 的同步边界，建立逐历元审计表：每个槽位的卫星、频点、旧/新参考星、SLIP/LLI/outage、初始化/重置原因、`P_amb` 前后值和变换类型。
2. 将审计表与 ignav `rtkpos.cc` 的 `refsat`、模糊度更新、DD 约束路径作语义比对。对参考星不同的历元，先显式变换到共同 DD 基底或只比较不依赖基底的指标；禁止把不同基底下的协方差相减。
3. 检查 TC 在 `sync_tc_ambiguities_with_rtklib()` 中从 TC 到 RTKLIB、经 `udbias()`、再回写 TC 的状态和协方差是否保持完整排列、对称性和交叉协方差；特别核对初始化槽位、清零槽位、未共同可见槽位和频率主序/卫星主序映射。
4. 若证据表明同步或重参数化后出现方差跳变、负特征值、条件数异常、状态残留或与 `first_cov_bad` 同时发生，则保留最小复现输入和矩阵快照，标记 `COV-F2-xx[Texp]`，再决定是否拟定代码修复。
5. 若按 ignav/RTKLIB 语义对齐后量测质量或精度恶化，立即回退、记录 `ASK-F2[Texp]`，并向用户请示；不得用放宽门限、增大 `prnbias` 或切换 AR 掩盖恶化。

### Phase F3：RTK-TC 浮点协方差耦合与反馈边界对照

1. 固定已通过的纯 RTK float 输入与观测条件，运行 RTK-TC float，不启用 AR；提取每个更新点的 `pre/post` 位置、速度、姿态、ba、模糊度方差和交叉协方差。
2. 利用已有诊断字段统计并画时间序列：`pre_amb_var_median`、`post_amb_var_median`、`pre_pos_amb_cov_norm`、`h_amb_max`、`k_amb_norm`、`S` 对角中位数、`K_pos/K_vel/K_att/K_ba`、innovation、相位/伪距有效数和反馈向量。
3. 对每个 `first_cov_bad` 前后窗口，比较更新前后 E/N/U 位置与速度修正，检查 E 向速度反馈是否与模糊度方差、交叉协方差、参考星切换或相位残差同步变化。
4. 同时对照 ignav 的更新点 `.stat` 与可获得的 trace/solution 状态；ignav 高频输出频率不同，不逐行硬比，而以整数秒更新点、相同区间增量、可见卫星和解状态为准。
5. 判定：若 TC 相比纯 RTK 新引入 `P_pos-amb` 断裂、异常 `K_amb` 或与 E 向反馈同相的协方差事件，转入 Phase F4；若 TC 协方差连续且残差/反馈不解释振荡，记录“GNSS 浮点协方差未证实为主因”，回交 `8-24ba优化.md` Phase D。

### Phase F4：量测权重、创新协方差与后验门控分解

1. 在完全冻结的状态/模糊度管理下，对同一观测集合逐项分析 `R` 的载波/伪距分量、仰角/CNR/星座因子、DD 相关项和 `S=H·P·Hᵀ+R`；不得同时调整 `R`、`P_amb`、AR 或 INS 过程噪声。
2. 报告相位和伪距各自的残差 RMS、归一化创新、接受/拒绝计数、post-fit 失败、降级与重启；将其与 E 向速度振荡和参考星切换做时间相关分析。
3. 先验证纯 RTK float，再验证 RTK-TC float。候选只能改变一个严格相关的权重变量族，且每个候选均先进行相同精度评估后再保留。
4. 若参考 ignav 的 `R` 或后验检验语义导致目标窗口、固定最差窗口或全段任一关键精度恶化，立即回退到 FINAL4，记录 `ASK-R[Texp]` 并停止该方向，等待用户决定。

### Phase F5：闭环验收与移交

1. 每个通过候选必须先重跑纯 RTK float，再重跑 RTK-TC float，完成目标窗口、固定规则最差机动窗口和全段三窗口评估。
2. 同时报告位置/速度/姿态真值误差、更新点和传播点分开指标、浮点质量、`P/K/S` 健康度、参考星/周跳/重置事件、降级和 `first_cov_bad[Tdata]`。
3. 只有下列条件同时满足，才可进入代码或配置修改执行计划：纯 RTK 与 TC 的协方差差距已定位到单一状态传播、重参数化、观测权重或门控路径；诊断可重复；且候选改动预期能在不恶化三窗口精度和纯 GNSS 结果的前提下消除该差距。
4. 若浮点协方差未能解释 E 向振荡，明确关闭本任务并将证据写回 `8-24ba优化.md`，优先转入姿态/初始化可观测性或独立量测系统误差任务。

## 6. 统一评估、回退与请示纪律

### 6.1 固定评估指标

每个基线、诊断候选和修复候选必须使用相同真值、时间匹配、整数秒更新点规则、坐标变换与异常样本规则，报告：

- 目标窗口 SOW `359000--359100`、预先选定最差机动 100 s 窗口、完整重叠区间约 SOW `357460--359815` 的 E/N/U、水平、3D RMSE；
- 更新点与传播点的 E/N/U 速度、水平速度、3D 速度误差和区间增长；
- 纯 RTK float 与 RTK-TC float 的有效历元、相位/伪距可用数、float/fix 状态比例、拒绝/降级/重启数；
- `P_pos`、`P_vel`、`P_amb`、`P[pos,amb]`、`P[vel,amb]`、`S`、`K_pos/K_vel/K_att/K_ba/K_amb` 的量级和健康诊断；
- 参考星、周跳、LLI、outage、模糊度初始化/重置与 `first_cov_bad[Tdata]`。

### 6.2 回退条件

立即保留证据并回退到最近通过基线：

- 目标窗口、固定最差窗口或全段任一关键精度恶化；
- 纯 RTK float 结果退化、有效相位减少、错误固定、降级/重启增加或出现长时间位置偏移；
- 协方差出现非有限值、无法 Cholesky 分解、明显负特征值、异常条件数或未经解释的参考星切换断裂；
- 只降低短窗口协方差或速度波动，却扩大真值位置/速度误差；
- 多个变量被叠加修改，导致无法归因。

### 6.3 必须请示的边界

出现以下任一条件时记录 `ASK-xx[Texp]`，保留前后配置、输出和矩阵诊断后暂停自主修改：

- 直接对齐 ignav/RTKLIB 的模糊度状态、DD 重参数化、`R`、`S`、后验检验或参考星语义后，三窗口或纯 GNSS 精度恶化；
- 需要新增/修改评估脚本、真值匹配规则、状态字段定义或输出格式才能继续判断；

### 结论

1. **速度统计对 eratio 完全不敏感**（upd/prop/growth 六位精度一致）：TC 速度信息由相位主导，
   码方差只影响位置通道——"eratio 降低改善振荡"的假设不成立；
2. eratio 是纯权衡轴：降低 → 窗口位置单调恶化（N 向缓漂 −0.13m@359090）+ 全段/U 单调改善
   （全段最多 −17%）；
3. 提高 vel_var_floor 无法挽回窗口损失（反而全面恶化）；elmin=15 对窗口无补；
4. 在"当前精度为底线"约束下，**联合调优空间已穷尽，FINAL4/B0-BA 维持为唯一通过配置**。
