# 本项目与 `tools/ignav` 的零偏估计：可复现实证对比

## 1. 目标与边界

本 issue 的目标不是让两条零偏曲线看起来相同，而是逐层确认以下链路是否一致，或确认差异是否有意且可解释：

```text
IMU 原始值/坐标系/单位
    -> 名义机械编排中的零偏补偿
    -> 误差状态 F、Phi、Q 与初始 P
    -> RTK 原始双差量测的 H、R 和模糊度状态
    -> P 的交叉协方差把位置/姿态残差传给 ba/bg
    -> Kalman 更新、闭环反馈、状态清零与 .stat 输出
```

零偏没有独立真值时，`ba/bg` 只能视为组合滤波的内部等效补偿；它可能同时吸收真实传感器零偏、比例因子、安装角、时间同步、未建模比力、GNSS 浮点残差和真值/杆臂残差。禁止仅因为某条曲线“接近 0”或“接近 ignav”就宣称标定正确。

本 issue 只比较 `tools/ignav` 与本项目的 RTK-TC 链路；`data/rtdtc.yaml` 是 RTD（仅码双差，可选 Doppler），没有载波模糊度状态，不能与 RTK 的相位零偏可观测性混为一谈。

## 2. 当前对照基线必须先冻结

当前两个配置并不完全同条件，任何数值差异必须先标注这一事实：

| 项目 | `tools/ignav` 当前参考 | 本项目当前 RTK-TC |
|---|---|---|
| 配置文件 | `data/ignav-rtktc.conf` | `data/rtk-ins紧组合.yaml` |
| GNSS 模式 | INS tightly coupled | `positioning_mode: rtk`, `ins.enabled: tc` |
| 星座 | `pos1-navsys=33`，GPS+BDS | `gnss_t: [GPS]` |
| 频率/高度角 | L1 / 10° | 1 频 / 10° |
| 模糊度固定 | `pos2-armode=off` | `armode: 0` |
| IMU 坐标 | RFU (`ins-imucoors=2`) | RFU，输入时转换至内部 FRD/ECEF 链路 |
| 杆臂 | 固定零杆臂 | 固定零杆臂 |
| 协方差传播节奏 | `ins-updint=1`，IMU 历元 | 每个有效 IMU 历元 |

因此，当前 `.stat` 的差异不能直接归因于“零偏算法不同”：GPS+BDS 与 GPS-only、不同码相位权重、不同星数和不同高度几何都会改变 `P[pos/att, ba/bg]`，进而改变零偏更新。

受控实验至少要固定：rover/base RINEX、星历、基站 ECEF、GPS-only、L1、10° 截止角、前向方向、同一 IMU 时间转换、同一初始化窗口及同一 GNSS 更新时刻。完成 GPS-only 对照后，才能单独评估 BDS 带来的变化。

## 3. 状态语义与单位

两边都使用闭环误差状态。下列量必须在比较前逐项确认：

| 项 | ignav | 本项目 | 比较要求 |
|---|---|---|---|
| 陀螺零偏 | `bg`，rad/s | `gyro_bias`，rad/s | 同一机体系、同一正负号 |
| 加计零偏 | `ba`，m/s² | `accel_bias`，m/s² | 同一机体系、同一正负号 |
| 误差状态次序 | `att, vel, pos, ba, bg, ...`（索引由 `ins-gnss-state.cc` 管理） | `[pos_e, vel_e, psi_e, bg, ba, optional...]` | 不能按数组下标直接抄写 |
| 名义状态更新 | `ba/bg += delta` | `gyro_bias/accel_bias += delta` | 对照反馈前后的物理状态，不是 error state |
| 机械编排补偿 | 由 `ins_errmodel2()` 使用已校正 IMU | `gyro/accel - bias` 后积分 | 用单样本注入验证符号 |

### 3.1 输出字段是诊断字段，不等于完整状态真值

- ignav `$GBIAS` 输出 `sol.bg[0:3]`，单位 rad/s，但仅保留四位小数；`0.0000` 可能只是绝对值小于 `5e-5 rad/s`。
- ignav `$ABIAS` 的源码实际写为 `sol.ba[0], sol.bg[1], sol.bg[2]`，所以只有 X 轴是真实加计零偏；Y/Z 绝不可绘制或参与统计。
- 本项目 `RTKINS.stat` 文件头声明 `$GBIAS` 和 `$ABIAS` 均为真实三轴、单位分别为 rad/s 与 m/s²，精度高于 ignav 输出。
- ignav `$INSTA` 行没有换行尾，后续 `$POSI` 可能粘连；解析时必须按 `$` 分割，而非仅按行分割。

当前文件尾部的可见值仅可作为检查样本：

```text
GInsStream @359817: bg=[+1.369e-4,-1.78e-5,-2.7e-6] rad/s
                         ba=[-3.606e-2,-1.939e-2,+1.660e-2] m/s²
ignav      @359817: bg=[+3e-4, 0, -2e-4] rad/s  (四位小数输出)
                         ba_x=-5.63e-2 m/s²; ABIAS Y/Z 无效
```

比较前应统一导出至少 `%.9g` 精度的三轴 `ba/bg` 和 1σ，不得由四位小数 `.stat` 反推收敛速度或白噪声强度。

## 4. 初值与初始协方差：当前已知差异

### ignav

`data/ignav-rtktc.conf` 给出：

```text
ins-uncba = 4.8901633857e-2 m/s²
ins-uncbg = 2.4240684055e-5 rad/s
ins-baopt = 1
ins-bgopt = 1
```

这表示三轴 `ba/bg` 都进入滤波状态，且初始 1σ 分别约为 0.0489 m/s² 与 2.424e-5 rad/s。该配置中未显式给出非零的物理 `imuerr.ba/bg` 初值；运行前还须确认 `prcopt_.insopt.imuerr` 的默认值或输入标定文件，不能把 `unc` 误解为 bias 初值。

### 本项目

`data/rtk-ins紧组合.yaml` 当前设置为：

```yaml
initial_gyro_bias: [0, 0, 0]            # deg/h
initial_acce_bias: [-2995.8, -1523.5, 1554.1] # mGal
gyro_bias_std_si: [2.424e-5, ...]       # rad/s
acce_bias_std_si: [0.005, 0.005, 0.005] # m/s²
```

其中加计初值约为 `[-0.0293, -0.0149, +0.0152] m/s²`，而且先验标准差从 ignav 的 `0.0489 m/s²` 收窄至 `0.005 m/s²`。这是一项有意的数据集等效补偿策略，不是对 ignav 初值的复刻；它会显著降低滤波器把残差重新分配给 `ba` 的能力。

### 必须比较

1. 初始化完成时的物理 `ba/bg`、error state `x`、`diag(P_ba/P_bg)` 与交叉块 `P[vel,ba]`、`P[att,bg]`。
2. 第一个 GNSS 更新前后，分别记录 `delta_ba/delta_bg`、反馈后的物理 bias 和 `P` 对角。
3. 分别用“ignav 零初值+宽先验”“本项目 ba*+窄先验”做交叉实验；每次只改变初值或先验其中之一。
4. 以 m/s² 和 rad/s 保存原始值；mGal、deg/h 只允许在报表展示层转换。

## 5. 随机过程与 Q：目前不一致，且影响不可忽略

### 5.1 ignav 的模型

`ins-baproopt=3`、`ins-bgproopt=3` 对应 Gauss-Markov。源码固定相关时间为 `CORRETIME=360 s`：

```text
b(k+1) = exp(-|dt|/360) · b(k) + w(k)
Q_b    = PSD_b · |dt|
```

在 `ins-gnss.cc` 中，`getQ()` 直接向 bias 对角写入 `psd.ba/bg * |dt|`；`stochasticPhi()` 写入 `exp(-|dt|/360)`；闭环误差均值随后清零。

### 5.2 本项目的模型

`src/core/ins/transfer_matrix.py` 固定：

```text
tau_bg = tau_ba = 0.01 h = 36 s
F_bg,bg = -I/36
F_ba,ba = -I/36
Q_bg = PSD_bg · dt
Q_ba = PSD_ba · dt
```

因此本项目也使用 Gauss-Markov，但 bias 向零衰减比 ignav 快 10 倍。两边 PSD 数值当前相同：

```text
PSD_bg = 2.61160339323310e-14 rad²/s³
PSD_ba = 1.66067346797506e-09 m²/s⁵
```

这不是“已经与 ignav 对齐”。若保持相同 PSD，36 s 的恢复力会改变稳态 `P_b`、bias 均值、相关性与 GNSS 更新时的 `K_ba/K_bg`。

### 5.3 Q 结构需要分项核对

| 项 | ignav | 本项目 | 结论/检查 |
|---|---|---|---|
| 传感器噪声 | `getQ()` 直接以 PSD×dt 写误差状态对角 | `G·Qdiag·Gᵀ` | 对各向同性三轴 PSD，旋转后数值等价；必须用实际 `C_b_e` 数值验证 |
| bias 噪声 | bias 对角 `PSD×dt` | bias 对角 `PSD×dt` | 基础 Q 幅值相同 |
| bias Phi | 360 s GM | 36 s GM | 当前确定不一致 |
| 位置随机游走 | ignav TC 无额外 pos PSD | 当前 `pos_psd=0` | 当前一致 |
| 速度随机游走 | ignav 无额外 `vel_psd` | 当前 `vel_psd=0`，但有 `vel_var_floor=3e-4` | 运行点仍不完全等价 |
| 可选状态 | 可按开关估计杆臂、时间差、比例因子等 | 当前固定零杆臂，部分可选块关闭 | 先冻结开关再比较 bias |

必做的数值证据不是只读配置，而是在同一 IMU 历元 dump `Phi_bg/bg`、`Phi_ba/ba`、`Q_bg/bg`、`Q_ba/ba`、`P` 传播前后值和特征值。

## 6. F 矩阵、可观测性与交叉协方差

两边的核心可观测链应为：

```text
bg --C_b_e--> attitude error --f_b×--> velocity error --dt--> position error
ba --C_b_e--> velocity error -------------------------------> position error
RTK DD phase/code residual --> position/attitude/ambiguity update
                                                \-> P cross-cov -> bg/ba update
```

### ignav

`getF()` 的关键块为：

```text
F_att,bg = +C_b_e
F_vel,ba = +C_b_e
F_vel,att = -[C_b_e f_b×]
F_pos,vel = I
```

RTK TC 的 `ddres()` 直接建立位置、姿态（非零杆臂时）、杆臂和模糊度的 Jacobian；`ba/bg` 没有直接伪距/相位观测列，主要依靠上述传播和 `P` 的交叉块更新。

### 本项目

`TransferMatrix.build_F[_ins]()` 使用同一基础链：

```text
F_vel,ba = +C_b_e
F_att,bg = +C_b_e
F_vel,att = -[C_b_e f_b×]
F_pos,vel = I
```

`RtkTcMeas._build_dd()` 的 RTK 双差量测直接写入位置、杆臂姿态和模糊度列；同样没有 `ba/bg` 直接列。故比较 `H_ba` 或 `H_bg` 为零是正常现象，真正应比较的是：

```text
P[ba, pos]、P[ba, att]、P[ba, amb]
P[bg, att]、P[bg, pos]
K_ba、K_bg、delta_ba、delta_bg
```

若 `K_ba≈0`，不能直接归咎于“PSD 太小”；须依次检查：姿态/速度误差、`P[vel,ba]` 是否形成、RTK 相位是否被接受、模糊度是否初始化、量测是否被 post-fit 拒绝、以及 bias 先验是否过窄。

## 7. RTK 量测端必须和零偏一起比较

零偏曲线不同往往是量测端不同的结果。每个 bias 对比实验必须同时记录：

| 类别 | 必须记录的细节 |
|---|---|
| 观测集合 | 星座、频点、共视卫星数、参考星、仰角、SNR、基线长度、rover/base 时间差 |
| 观测类型 | 相位 DD 数、码 DD 数、是否有 Doppler、码/相位残差分布 |
| 模糊度 | 每星初始化/重置/周跳、`P_N`、`P[pos,N]`、LAMBDA ratio、FIX/HOLD 状态 |
| R 模型 | `eratio`、相位/码误差常数、仰角项、卫星钟项、SNR 项、鲁棒降权和拒绝门限 |
| 接受情况 | attempted/accepted phase、attempted/accepted code、被拒原因、post-fit χ²/单残差检查 |
| Kalman 结构 | `S` 对角/条件数、`K_pos/K_att/K_ba/K_bg`、更新前后 `P` 对称性与最小特征值 |
| 反馈 | `delta_pos/vel/att/ba/bg`、反馈时刻、是否清零 error state、名义状态更新后的残差 |

当前配置中的重要差异：

- ignav：GPS+BDS、`pos2-armode=off`、相位/码创新门限 `pos2-rejionno=30 m`。
- 本项目：GPS-only、`armode=0`、`eratio=[300,100]`、`maxinno=5 m`、`maxcode=30 m`。
- 当前两边都没有 integer fix，但码/相位权重、星座和相位拒绝策略并不相同；这足以改变高度通道与零偏交叉协方差。

本项目 RTK TC 采用 Joseph form 更新并在 post-fit 拒绝时事务性回滚；ignav 的 `filter()` 使用 `(I-KH)P` 并仅更新正方差活动状态。两者在良态条件下应数值接近，但必须比较实际的 `S/K/P`，不能仅比较公式名称。

## 8. 闭环反馈与状态保存

### ignav

`lcclp()` 对位置、速度、姿态作闭环修正，对 `ba/bg` 执行 `bias += delta_bias`。`propx()` 随后将闭环误差状态置为近零。RTK TC 路径在 `rtkpos.cc::relpos()` 中也会对临时 INS 副本 `clp()`，通过 post-fit 后再写回 INS。

### 本项目

`TcEstimator.tc_meas_update()` 调 `joseph_update()` 后调用 `feedback()`；`LcEstimator.feedback()` 执行：

```text
pos_true   = pos_nominal - delta_pos
vel_true   = vel_nominal - delta_vel
C_b_e      = R(-delta_psi) · C_b_e
bg_true    = bg_nominal + delta_bg
ba_true    = ba_nominal + delta_ba
x_error    = 0
```

当前 `feedback_pos_enable: off`，即位置立即闭环，避免把“位置反馈比例”当成当前 bias 差异来源。若重新开启平滑反馈，必须把残留位置 error 的 Phi 传播和 bias 交叉协方差一起纳入对照，不能只比较更新点的 `$ABIAS`。

## 9. 建议的最小诊断数据格式

每个 GNSS 更新点输出一行 CSV；所有值使用 SI 单位和至少 9 位有效数字：

```text
week,sow,mode,gnss_system,n_phase_acc,n_code_acc,ref_sats,
ba_x,ba_y,ba_z,bg_x,bg_y,bg_z,
P_ba_x,P_ba_y,P_ba_z,P_bg_x,P_bg_y,P_bg_z,
P_vel_ba_norm,P_att_bg_norm,P_pos_ba_norm,
K_ba_norm,K_bg_norm,delta_ba_norm,delta_bg_norm,
innovation_norm,S_diag_median,postfit_chi2,update_accepted,
amb_ratio,amb_fixed,reset_or_slip_event
```

另外单独保存首次 10 个 IMU 历元和每次 GNSS 更新前后的完整 15×15 基础 `P` 块、`Phi`、`Q`。只保存对角线不足以判断 `ba/bg` 是否可观。

## 10. 分阶段实验顺序

1. **格式层**：修复/绕开 ignav `$ABIAS` Y/Z 输出错误；统一 body-frame、SI 单位、时间标签、精度和 update mask。
2. **冻结 GNSS 层**：GPS-only、L1、AR-off、同一阈值与 `eratio`；先验证每历元 DD 卫星对、残差和 R 一致。
3. **冻结初始化**：两边都使用 bias=0+相同宽先验，或都使用同一个 ba*+相同窄先验；不得混合比较。
4. **单变量比较 tau**：本项目分别取 36 s、360 s；保持 PSD、初始 P、GNSS 更新完全不变。
5. **单变量比较 Q**：比较直接 `PSD×dt` 与 `G·Q·Gᵀ` 的实际数值；确认没有额外 `vel_psd`、floor 或可选状态改变运行点。
6. **单变量比较反馈**：立即闭环对立即闭环；记录每次 `delta_ba/bg` 和反馈后物理 state。
7. **验收**：每个候选同时报告目标窗、预登记最差窗和全段的 E/N/U、水平/3D、更新点/传播点、速度、姿态、有效相位率、降级率与 `P` 正定性。

禁止以“零偏更接近 ignav”替代真值精度验收；也禁止通过只调大 `P_ba`、PSD 或 GNSS 权重掩盖量测模型/模糊度问题。

## 11. 当前可验证结论与待验证项

### 已确认

1. 两边 bias PSD 数值相同，但相关时间不同：ignav 360 s，本项目 36 s。
2. 两边 RTK 双差量测都不直接观测 `ba/bg`；bias 更新依赖传播和交叉协方差。
3. ignav `$ABIAS` 只能使用 X 轴；本项目 `$ABIAS` 可使用三轴。
4. 当前本项目的非零 ba* 初值和窄 `P_ba` 不是 ignav 的同条件复刻。
5. 当前 GNSS 星座与码/相位权重不同，任何当前 bias 数值比较都含混杂因素。

### 尚待通过数据证明

1. `tau=36 s -> 360 s` 是否改善 bias 物理可解释性，而不损害三窗口精度和稳定性。
2. 本项目和 ignav 在同一 GPS-only、AR-off 条件下的 `P[vel,ba]`、`P[att,bg]`、`K_ba/K_bg` 是否一致。
3. 高程残差进入 `ba` 的比例是否来自浮点模糊度/码权重，还是来自 IMU 比力/姿态模型。
4. 现有 ba* 在不同时间窗、不同初值和纯机械编排回放中是否稳定；不稳定则只能标注为数据集等效补偿。
5. 使用高精度 debug 输出后，ignav 的实际 `ba_y/ba_z` 是否与本项目同方向、同机体系和同数量级。

## 13. 执行记录（2026-09-07，36 s 基线与 360 s 候选）

### 13.1 执行范围与代码改动

按本 issue 的顺序完成了“冻结基线 → 传播/更新诊断 → tau 单变量实验 → 三窗口验收”。本轮只新增诊断能力和可选相关时间参数，没有改变正式配置中的 GNSS、初值、PSD、反馈、门限或 AR 设置。

- `TransferMatrix` 新增 `ins.gyro_bias_corr_time_s` / `ins.acce_bias_corr_time_s`，缺省仍为 36 s，并拒绝非有限或非正值。
- TC 估计器保存最近一次基础 15×15 `P_before/P_after/Phi/Q` 快照。
